**### Design**

\`apc.utils.model\_bundle\` implements the design contract's dataclasses close to the letter of section 2 (\`ComponentManifest\`, \`PrimitiveManifestEntry\`, \`RouterManifest\`, \`ArgumentScorerManifest\`, \`ScoringPolicyManifest\`, \`ModelBundleManifest\`), a \`BuildRoute\`/\`BundleScope\`/\`PublishStatus\`/\`ProvenanceStatus\` enum set, and 13 typed \`ModelBundleError\` subclasses (\`MISSING\_ARTIFACT\`, \`CORRUPTED\_ARTIFACT\`, \`CORE\_DEPENDENCY\_MISMATCH\`, \`SCHEMA\_MISMATCH\`, \`ARGUMENT\_SCHEMA\_MISMATCH\`, \`ROUTER\_KEY\_MAPPING\_MISMATCH\`, \`EXECUTION\_SIGNATURE\_MISMATCH\`, \`UNTRAINED\_COMPONENT\`, \`UNKNOWN\_PROVENANCE\`, \`UNCERTIFIED\_PAIR\`, \`INCOMPLETE\_BUNDLE\`, \`CAPABILITY\_NOT\_QUALIFIED\`, \`DUPLICATE\_TRAINING\_IDENTITY\`) -- a superset of the design doc's own illustrative label list. \`load\_bundle(manifest, mode, required\_capabilities, ...)\` is read-only: it never imports or calls a builder/optimizer/trainer, and performs, in order, manifest self-consistency, capability/scope gating, publish-status, structural completeness, provenance, Core integrity, decoder/vocabulary integrity + cross-component schema agreement, per-primitive integrity **\*\*and the Core-dependency check that is the whole point of this task\*\*** (\`entry.core\_dependency\_hash != manifest.core.canonical\_state\_hash\` -> \`CoreDependencyMismatchError\` -- exactly the check ADR-0091's bug lacked), argument-schema consistency, router integrity + key-to-primitive mapping, argument-scorer integrity, router/scorer pair compatibility, and execution-signature agreement.

Two independent hashes are kept per component throughout: \`file\_sha256\` (raw bytes) and \`canonical\_state\_hash\` (tensor name/shape/dtype/content, independent of pickling metadata) -- a byte copy matches both, independently trained weights match neither, a re-serialized copy of the same weights matches only the canonical one (\`raw\_file\_sha256\`/\`canonical\_state\_hash\`/\`canonical\_state\_hash\_from\_file\` in \`model\_bundle.py\`; property-tested in \`tests/test\_model\_bundle\_contract.py\`).

Two design corrections were made during implementation, both confirmed necessary by a failing test before the fix:

1\. **\*\*\`compute\_content\_manifest\_digest\`'s payload originally embedded \`file\_path\`/\`source\_artifact\` (filesystem locations).\*\*** This made \`bundle\_id\` differ for two bundles holding byte-identical content at different paths -- wrong, since a namespace copy of the same weights is the same content per the design doc's own restore-vs-build distinction. Fixed by building the digest payload from explicit content-only field extractors (\`\_component\_digest\_payload\`, \`\_primitive\_digest\_payload\`, \`\_router\_digest\_payload\`, \`\_argument\_scorer\_digest\_payload\`) that omit path and free-text (\`training\_receipt\`) fields. Caught by \`test\_bundle\_id\_deterministic\_for\_identical\_content\`.

2\. **\*\*\`RouterManifest.weights\_hash\` originally covered the router's full \`state\_dict\`, including its per-primitive \`\_keys.\<id>\` entries.\*\*** This made a two-key swap (the "bank key順序交換" required test) indistinguishable from a general router-weights corruption -- both raised \`CORE\_DEPENDENCY\_MISMATCH\` before the key-mapping check was ever reached. Fixed by introducing \`router\_non\_key\_state\_dict\` (excludes \`\_keys.\*\`) so \`weights\_hash\` covers only the router's shared parameters (\`query\_proj.\*\`), while \`key\_to\_primitive\_mapping\_hash\` (content-addressed per id, order-independent) separately and specifically catches a swapped/corrupted key.
