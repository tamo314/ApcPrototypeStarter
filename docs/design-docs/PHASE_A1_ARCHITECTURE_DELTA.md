# Phase A.1 Architecture Delta

This document describes only changes from Phase A.

## 1. Revised objective

Phase A.1 separates representation learning, composition, novelty, routing, plastic learning, consolidation, and reuse. The core principle is: **prove behavior with oracle information, then replace one oracle at a time.**

## 2. Revised data flow

```text
Input
 ├─ task/control stream ─> Task Encoder ───> z_task
 └─ content stream ──────> Content Encoder -> h_content

z_task
  ├─ Oracle/Learned Novelty
  ├─ Oracle/Retrieval/Learned Router
  └─ Composition Search
              |
h_content ----+--> selected primitive/recipe execution --> output
                              |
                              +-- if insufficient --> Residual Plastic Workspace
                                                     |
                                                     v
                                             Functional Consolidation
                                                     |
                                      Primitive Bank / Composition Library
```

`z_task` is used for routing/novelty. `h_content` is the state transformed by primitives.

## 3. Online procedural environment

The main scientific path no longer trains on a small fixed dataset. Each step/batch generates fresh examples.

Required properties:

- deterministic under a run seed,
- effectively unbounded content combinations,
- per-batch or per-episode symbol permutation,
- constant abstract operation semantics,
- ground-truth K/C/N/R and primitive decomposition available to evaluation/oracle code only.

## 4. Task/content factorization

The Stable Core must expose separate task and content representations. Exact implementation is flexible, but learned routing/novelty must not depend solely on a low-information content state.

Gate: known operations must generalize to unseen content before APC mechanisms are evaluated.

## 5. True sparse Primitive Bank

Retain Phase A low-rank primitives, but execute only selected IDs.

Conceptually:

```python
selected_ids, weights = router(z_task)
selected = bank.gather(selected_ids)
delta = execute_selected(selected, h_content, weights)
```

Do not compute outputs for non-selected primitives.

The bank must support batched selected-ID gather, usage logging, functional probing, resident parameter count, and selected parameter count.

## 6. Composition Library

Recipes are distinct from primitives.

```text
recipe_17 = [primitive_2, primitive_7, primitive_3]
```

Store recipe ID, ordered primitive IDs, task-key prototype, usage count, and validation score. A C task should create/retrieve a recipe, not a new primitive.

## 7. Oracle Ladder

Provide explicit modes:

- Oracle K/C/N/R decision,
- Oracle primitive/recipe routing,
- Oracle recurrence routing.

Learned mechanisms are introduced only after the oracle predecessor succeeds.

## 8. Composition search

Before plastic expansion, search existing primitive compositions. Initial Phase A.1 may use exhaustive/beam search because the bank is intentionally small.

Suggested defaults:

- max depth: 3,
- beam width: 8-32,
- objective: validation loss/exact match on a small adaptation set.

Expansion is permitted only after composition search fails.

## 9. Residual Plastic Workspace

Let `F_existing` be the best available primitive/recipe solution. Plastic capacity learns only the residual:

`F_target(h) ~= F_existing(h) + R_plastic(h)`

Keep a full-task plastic path as an ablation/control.

## 10. Compressibility-controlled N operations

At least one N family is generated by hidden low-rank ground-truth transforms. The learner never receives the ground-truth weights.

Example first case:

- ground-truth rank = 4,
- temporary workspace = 16 x rank-4 transforms or comparable capacity.

This makes compression falsifiable: a compact equivalent is known to exist.

## 11. Functional consolidation

Consolidate the **function**, not the temporary weights.

Procedure:

1. collect `(h, delta_h)` probes from generated train and held-out content,
2. evaluate temporary residual outputs,
3. fit candidate primitives at increasing ranks,
4. choose the smallest candidate meeting functional and task thresholds,
5. causal/task validate,
6. run shadow validation,
7. install and release temporary capacity.

## 12. Retrieval-first recurrence

Before reintroducing a learned router, store task-key prototypes with primitives/recipes:

`k_i = mean(z_task)` over successful examples.

Retrieve by similarity. This is an interpretable bridge between oracle routing and learned routing.

## 13. Learned computational novelty

The desired novelty is not “unusual input”; it is “existing computation is insufficient.”

Start with:

- residual loss after best existing recipe,
- retrieval confidence/task-key distance.

Optional later experiment:

`N_grad = ||g_perp|| / ||g||`

where `g_perp` is the new-task gradient component outside an existing primitive/task gradient subspace.

## 14. Correct accounting

### Resident total
Stable Core + persistent primitive/recipe learnable parameters.

### Resident primitive
Persistent Primitive Bank only.

### Active total
Stable Core + primitives actually executed for the sample/batch.

### Active primitive
Only selected/executed primitive parameters.

### Temporary peak
Maximum simultaneous Plastic Workspace capacity.

Cross-baseline plots must use identical definitions.

## 15. Out of scope

Phase A.1 must not add:

- RL meta-controller,
- language-model integration,
- semantic memory,
- million-expert indexing,
- custom CUDA kernels,
- distributed training,
- dense-teacher mechanistic circuit extraction.
