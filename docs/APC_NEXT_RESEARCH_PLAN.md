# APC 次期研究計画 — 機構の動作確認から、局所獲得・再利用の比較実証へ

作成日: 2026-09-24（JST）  
対象: tamo314/ApcPrototypeStarter、main `113aa63161438c4de88fe0f9647dc8d9d7197e08`  
適用範囲: `experiments/maniskill/`  
状態: 提案。新しい学習・物理シミュレーションは本計画の作成時には実施していない。以下の既存成績はリポジトリの記録値であり、今回の再測定値ではない。

## 1. 研究判断

局所身体性プリミティブを毎step選択する方針は維持する。次の主題は、銀行エントリ数や実装済み機能数を増やすことではなく、次の問いを比較可能な実験にすることである。

> 同一の身体操作と目標表現を使う単一セレクターに対し、APCは不足する局所能力だけを学び、定着・解放後の再出現で追加学習費用を減らせるか。その際、過去能力と総保存容量はどう変わるか。

少数成功は機構の動作確認として扱う。教師あり獲得、自動トリガー、教師なし探索、独立評価を混同しない。成功率によるフェーズゲートは設けない。

## 3. 維持する設計

有限の20 ID、毎stepの直接選択、IK/PD実行器、保持目標、幾何相対観測、既存の物理制約検査を維持する。高水準のnavigate/grasp_lift等を新しい固定マクロIDに戻さない。

銀行内エントリの役割を、身体操作本体、全体セレクター、局所セレクター補正に区別して記録する。現状は主としてセレクターの銀行であり、身体操作本体の自動発見とは呼ばない。

新しい局所セレクターも既存20 IDに対する判断を返す。毎stepの切替で物理状態、保持目標、指幅目標をresetしない。目標位置と達成条件は入力してよいが、正解Candidate IDや教師stageは推論入力に含めない。

## 4. 優先する実験

### P0: 記録の修正と同条件比較を、最初の実runと一緒に行う

APC_RESEARCH_SUMMARY.mdへ証拠範囲を追記する。過去runは上書きせず、dummy実証をfixtureと明示し、モデル実績から分離する。fixtureエントリを実行用銀行に混ぜない。

既存runner・集計器を拡張し、同一初期条件、目標、step予算、成功定義で現行CARTと教師を比較する。保存済みデータが利用できる場合は先に再集計し、再実行は必要な条件だけにする。

記録する最小出自は、commit/dirty snapshot、環境config、物理初期状態、seed用途、feature schema、モデルhash、教師データhash、ラベル生成元、学習/検証分割である。summaryとcheckpointでschemaが食い違う場合は実checkpointを基準に記録する。

seed用途はtrain、development、holdout、retentionに分ける。一度失敗分析や調整に使ったholdoutはdevelopmentへ移し、独立評価には新しい条件集合を割り当てる。環境seedと学習乱数seedは別々に管理する。

出力は小さい比較表と失敗例の診断。文書整備だけを独立した長期工程にしない。

### P1: 失敗する局面を特定し、必要な変更だけを試す

最初に区別する失敗は、接近/IK、姿勢/経路拒否、閉指/把持、把持喪失、目標未到達、到達後の静止・保持である。episode全体だけでなく最初の分岐と直前・直後の状態を読む。

| 観測される障害 | 一度に試す変更 | 避けること |
|---|---|---|
| 到達後に静止条件を満たせない | 手先/物体速度、関節速度要約等の追加を単独比較 | 根拠なくGRUや大型モデルを導入する |
| 閉指待機や把持喪失の判断が不安定 | 実指幅、閉指経過時間、短い把持履歴のうち必要なものを比較 | 教師stageを推論入力へ入れる |
| learnerが訪れた状態で教師行動と不一致 | 実状態に同期した教師で失敗局面だけ再ラベル | 成功教師軌跡を無差別に増量する |
| IK/経路側が同じ状態で実行不能 | 目標刻み幅・姿勢・IK候補を局所比較 | セレクター学習だけで制御器不足を解こうとする |

現行特徴には目標経過時間等があるため、時間情報が全くないとは解釈しない。追加特徴は既存情報との重複を確認する。教師問い合わせと介入は分けて記録し、評価時は両方0にする。

初回は既知の失敗条件3–5 episode/variant、最大1200 step/episodeを目安とする。結果を見て一つの変更を選び、次の小runへ進む。100%成功を待たない。

### P2: タスク別銀行が必要かを、単一の目標条件付きモデルと比較する

現在のPick/Place差は主に目標の違いである。目標位置をパラメータ化した共通環境で、左右・前後・高さを一軸ずつ変える。到達可能性や接触が不明な変更は短い診断を先行する。

比較するのは、(a)単一の目標条件付きCART、(b)同データの小型MLP、(c)既存のタスク別銀行＋タスクラベルルーターである。身体操作、観測、教師データ総量、物理制約、評価予算を揃える。cは正解タスクラベルを使う対照であり、ラベルなし自律適応として報告しない。

現行train()は異なるtaskの教師sourceを拒否するため、混合学習を行う場合は共通のパラメータ化タスクと互換schemaを明示する。タスク整合性検査を無条件で無効化して混ぜない。

単一モデルが同等以上なら、目標ごとにCandidateを増やさない。次の局所獲得は目標変更では解決しない能力差へ向ける。銀行の有用性を否定・肯定するための比較であり、必ず銀行方式を勝たせる設計にしない。

### P3: 実モデルによる局所獲得→定着→解放をつなぐ

凍結した既存セレクターに対し、P1で観測した失敗局面の判断だけを補うTemporaryを学習する。初版では教師ありでよいが、教師あり獲得と明記する。新しい大きなタスク方策を一式複製することを局所獲得とは数えない。

実験の流れは次の通り。

1. Base単独とBase＋Temporaryを同条件で物理rolloutし、改善箇所と副作用を測る。
2. Temporary自身の判断、またはBase＋Temporaryの合成判断を教師として、コンパクトなCandidateを学習する。何を移転するかを明記する。
3. Candidateを実行して状態を収集し、必要な状態でTemporaryに再ラベルを問い合わせる。ラベル生成元hashと費用を保存する。
4. Base＋Candidateを物理rolloutし、行動一致率だけでなく最終成功・保持・拒否・接触を比較する。
5. 学習プロセスを終了し、Candidate/銀行/実行コードだけの最小バンドルを新プロセスで起動する。Temporaryやoptimizerを実行依存に含めない。
6. 旧課題と、獲得能力を必要とする別配置を追加学習なしで実行する。

同時に、同じ教師データから直接CARTを学習する対照を必ず置く。直接CARTで同等以上ならTemporaryを必須工程としない。Temporaryを介すことで初めて獲得できる能力、または実測できる費用削減があるかを研究対象とする。

CARTは勾配更新0でもfitは学習である。teacher calls、環境step、勾配更新、tree fitsを別々に集計する。

### P4: 能力不足を検出する、予算付き自動ループを作る

最初から複雑な確率モデルや未知検出器を作らない。進捗停滞、拒否の連続、把持喪失、学習範囲からの逸脱など、測定できる診断の組合せで適応要求を出す。これらは不足の確定証明ではなく探索トリガーである。

ループは「既存候補を試す→停滞等を検知→短いデータ収集→局所Temporaryの更新→実候補抽出→比較結果を保存→候補登録または旧候補保持→再試行」とする。成功率閾値で研究を停止しない。候補が悪化したらその候補を採用せず、失敗データを残して次の小変更へ進む。

find_candidate()の未知条件で先頭候補を返す挙動は、明示的なunknown/abstainへ変更する。タスク目標・達成条件は与え、正解スキル名は与えない。task_kindルーターは対照として残す。

選択確率や木の葉頻度を、そのまま課題成功確率と呼ばない。確率を採用判断に用いる場合は独立したエピソード結果との対応を測る。各stepの選択IDとactive entryを実ログから記録し、報告側に正解の候補名を固定文字列で書かない。

初版の学習器や教師が手設計なら「自動トリガー付き教師あり適応」と呼ぶ。教師なし獲得は、局所探索/RLを別比較で導入して初めて評価する。

### P5: 真の配置課題と、再出現による費用削減を試す

次の新課題は、目標位置をずらすだけでなく、支持面へ下ろして手放し、物体が静止する課題を提案する。新しい環境IDとconfigを与え、既存Placeの成績を新定義で書き換えない。

成功条件は、目標誤差、支持面上の高さ・支持接触、非把持、物体の並進/角速度、連続20 step維持をconfigで定義する。具体的閾値は測定して決める。物体と支持面の接触は許容し、腕と机などの不要接触と区別する。

最初は同じCubeと小さい支持面を使用し、複雑なアセット・画像認識・別ロボットを同時に導入しない。新たな身体操作IDが必要かは、既存IDでの診断から判断する。

課題列の例は、既知の把持保持A→目標変化B→真の配置C→別配置のA′→Cで獲得した能力を必要とする別配置D。A′で過去保持、Dで学習費用の再削減と局所能力の再利用を調べる。固定シードの単純再実行と未学習配置への転移を区別する。

## 5. 比較系と主要指標

APCの利得を、同じ20 IDを使う単一共有セレクター、タスク別独立モデル、局所追加型APCで比較する。まず小さい比較から始め、全組合せを一括実行しない。不要な連続行動BCの再実装は初回に含めない。

| 観点 | 記録するもの |
|---|---|
| 課題の成功 | 把持・持上げ・目標到達・最終成功・連続保持を個別記録 |
| 学習費用 | 新規環境step、教師問い合わせ、介入、勾配更新、tree fits、実wall time |
| 再利用 | 初遭遇と再遭遇の追加学習費用、更新0での新配置成功 |
| 定着 | TemporaryとCandidateの閉ループ性能差、全保存値数、容量差 |
| 保持 | 銀行更新前後で同条件の旧課題を実行した差。ルーターも含む |
| 制御 | 拒否原因、把持喪失、許容/不要接触、停止判定、数値発散 |
| 資源 | Active銀行bytes、Candidate数、重複数、実行中モデル数、プロセスRSS/peak RSS、アーカイブ容量 |
| 推論 | 特徴抽出、セレクター、IK、物理stepを分けた時間 |

Temporary解放の範囲は、実行依存、銀行内保存物、学習プロセス、実験アーカイブを区別する。過去研究のcheckpointを勝手に削除しない。勾配パラメータ0は総容量0でも、推論費用0でもない。

小runではnを必ず表示する。有望な変更だけ条件数や学習seedを増やし、条件別結果と不確実性を報告する。最大成功例だけを選んで一般性能としない。

## 7. 試行とテストの運用

3–5 episode/variant、最大1200 step/episodeを初回目安とし、1回の比較は原則2–3方式に絞る。これは研究実行時の予算提案であり、実行時間の予告や完了予定ではない。既存の保存データで答えられる問いに新規環境stepを使わない。

一つの大きな機能が完成した時点で、その入口から成果物までの統合テストを原則1本だけ作る。小修正は既存test_primitive_feature.pyへ反映する。獲得・定着・解放・別プロセス再実行を一つにつないだ時点で、必要ならtest_apc_cycle_feature.pyを1本追加する。

テストが検査するのは、実モデルの学習/保存/読込、Temporary非依存の推論、schema整合、銀行の整合、終了・出自・費用の記録である。タスク成功率はテスト合格条件にしない。dummyやskipを実物理の成功証拠としない。

失敗runは記録し、実行不能・数値発散・予算超過は当該runを区切る。研究全体の停止ゲートや文書承認には拡張しない。無関係な旧APC全体テスト、細分化unit test、カバレッジ目標は追加しない。

## 8. 研究結果による分岐

| 結果 | 次の判断 |
|---|---|
| 単一目標条件付きCARTが銀行と同等以上 | 目標ごとのエントリ増設をやめ、異なる達成条件や本当の能力不足へ進む |
| 教師ラベルから直接CARTがTemporary経由と同等以上 | Temporaryを儀式的に挟まない。Temporaryの利点が生じる条件を別に探す |
| Temporaryで改善しCandidateで退行 | 生徒自身が訪れる状態の追加収集、木の容量/分岐、局所適用範囲を一つずつ変更 |
| 新課題改善と旧課題退行が同時に起きる | 旧モデルの重みだけでなくルーター・適用領域・特徴変換を診断 |
| 再出現でも同量の学習が必要 | 再利用の適用条件と識別表現を見直す。再利用成功とは呼ばない |
| Candidateが課題数に比例して増え続ける | 共有モデルや重複統合と比較し、総容量と適応費用のトレードオフを評価 |

最も価値のある次の成果は、「銀行へ登録できた」ではなく「既存の判断を保ったまま局所能力を獲得し、実モデルを定着・解放した後の別配置で、再学習費用が減った」という比較可能な一例である。
