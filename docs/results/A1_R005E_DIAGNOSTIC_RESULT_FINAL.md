## 1. エグゼクティブ・サマリー（Executive Summary）

### 結論: **Branch B（共有クエリ可能表現 + 異種小型プリミティブ）の正式採択と、旧 A1-R006 の代替（SUPERSEDED）勧告**

A1-R005 の初期失敗から始まった長期にわたる診断シリーズ（A1-R005D, A1-R005E-001〜006A, S001〜S006）の全実証データを統合した結果、**APC（Adaptive Primitive Consolidation）の根本仮説である「1つの安定した共有表現空間 $\to$ 疎に呼び出される小型再利用可能プリミティブ」は完全に成立することが決定論的に証明された**。

### 5つの必須結論に対する確定判定

|---|---|---|---|
| **1** | E-006A の性能向上が単一共有エンコーダに一般化するか | **YES（一般化する）** | S001〜S003: 4演算すべてで共有エンコーダの保持率 $R_{\text{shared}} \ge 99.6\%$（干渉ゼロ） |

## 2. 診断の歩みと未解決課題解消の軌跡

### 2.1 A1-R005 / A1-R005D: 初期の失敗と交絡の同定
- **初期仮説の破綻**: 当初の A1-R005 では、Frozen Stable Core の出力に対して低ランク残差変換を行う `ConditionedPrimitive`（pointwise MLP / LoRA 類似構造）を用いていた。しかし、因果ギャップは BIND で `-0.005`（統計的ゼロ）、SELECT で `0.049`、SHIFT で `0.039` と完全に機能しなかった。
- **未解決の交絡**: この失敗が「Stable Core の表現空間にタスク情報が含まれていないためか（表現不全）」、それとも「点ごとの加算変換では位置置換や連想参照を解けないためか（演算子容量・構造不全）」が未分離であった。

### 2.2 A1-R005E-002 / 003: 表現プローブによる事前確認
- 線形プローブおよび非線形 MLP プローブにより、Frozen Core の潜在表現 $h_{\text{content}}$ 内部にトークン同一性および絶対位置情報が線形分離可能な形で十分保存されていることを確認。

### 2.3 A1-R005E-004: 高容量演算子（C01）による上限性能の証明
- 3層双方向自己アテンション（244万パラメータ）を持つ `HighCapacityOperator` を Frozen Core の上に配置。
- SELECT（Correct 91.9%, Gap 0.895）、BIND（Correct 87.9%, Gap 0.586）が劇的に向上し、**「適切なクロス・自己アテンション構造があれば、Frozen Core の表現から因果的計算が可能である」** ことが実証された。ただし、244万パラメータはプリミティブとしては肥大化しすぎであり、原始関数スケールでの検証が急務となった。

### 2.4 A1-R005E-005: 標準小型演算子（C00）の不合格と混合結果
- 単一層のクロスアテンション（18k パラメータ）を持つ `CompactCrossPositionOperator` を Frozen Core の上で検証。
- 結果は全演算で不合格（SELECT: 33.5%, COUNT: 47.2%, BIND: 37.1%, SHIFT: 3.8%）。
- 依然として「表現の幾何学的アクセス性（accessibility）」と「小型演算子の表現能力（expressivity）」が交絡していた。

### 2.5 A1-R005E-006A: 要因配置 C10（同時学習）による表現アクセス性の劇的回復
- エンコーダと小型演算子を演算ごとに同時学習（Joint Training）したところ、SELECT は `100.0%`、COUNT は `99.7%`、BIND は `100.0%` へと驚異的な回復を遂げた（$R_{\text{access}} \gg 1.0$）。
- これにより、小型演算子の能力不足ではなく、**「凍結表現の幾何学的形状が小型アテンションにとってクエリしづらい配置になっていたこと（Representation Accessibility）」** が主因であると特定された。
- しかし、E-006A は演算ごとに独立したエンコーダを用いており、「演算ごとに別々のコアが必要なのではないか？」という重大な交絡が残された。

### 2.6 A1-R005E-S001〜S005: 共有クエリ可能表現ゲート（Branch B の実証）
- **S001〜S003**: 4演算で1つの共通 `DecoderOnlyTransformer` エンコーダを共有し、均等混合学習（25%ずつ）を実施。
  - その結果、E-006A に対する保持率 $R_{\text{shared}}$ は全演算で **`99.62%〜103.05%`** を達成。マルチタスク共有による表現の干渉や劣化は完全にゼロであることが証明された。
- **S004**: COUNT/BIND の None アーム上限（0.30）超過について監査を実施。引数なし時にモデルがタスクの自然な最頻値を出力するベースライン挙動（COUNT: 33.46%, BIND: 34.00%）であることを突き止め、不当な硬直的閾値を廃止してベースライン相対基準（$B_{\text{natural}} + 0.05$）を策定。
- **S005**: Branch B（Shared Queryable Representation）を正式採択（Outcome B）。

### 2.7 A1-R005E-S006: SHIFT 構造プローブによる最後の課題の完全解決
- S002/E-006A で唯一 ~52% で頭打ちとなっていた SHIFT に対し、凍結共有エンコーダを変更することなく、モジュラ相対位置アテンションバイアス（+128 パラメータ、計 18,282 params）を導入した `ShiftRelativeCrossPositionOperator` を検証。
- 結果は **Correct Exact 93.85% / Token Accuracy 99.17% / Causal Gap 90.83%** を達成し、完全合格（ALL PASS）。E-004 の巨大演算子（2.44M, 61.80%）を +32.1 pt も上回る最高精度を、133倍小型なプリミティブスケールで達成した。

## 4. 演算ごとの最終診断分類（Per-Operation Diagnosis）

| 演算 | 最終診断分類 | 律速要因と解消メカニズム |
|---|---|---|
| **SELECT** | **表現アクセス性（Representation Accessibility）** | 単一層クロスアテンションで容易に位置選択が可能。凍結初期表現ではアテンションが分散していたが、タスクブラインド共有学習により目的位置の潜在表現が極めて明瞭にクエリ可能となった。 |
| **COUNT** | **表現アクセス性 + 自然ベースライン効果** | 集約トークンへのクエリにより、小型アテンションで 99.55% 達成。None アームの見かけの高さ（~32%）はデータ生成分布の偏り（最頻値 33.46%）によるものであり、因果感受性は完全。 |
| **BIND** | **表現アクセス性 + 自然ベースライン効果** | キー・バリューの連想検索。初期は pointwise 構造のため機能しなかったが、共有クエリ可能表現 + クロスアテンションにより 99.98% 達成。None アームは末尾予測ベースライン（34.00%）に一致。 |

## 5. アーキテクチャ推奨事項と次期フェーズ仕様（Branch B）

本診断の結果を踏まえ、Phase A.1 以降のプロダクション・アーキテクチャの基本設計方針を以下のように確定・勧告する：

### 5.1 単一の共有クエリ可能表現（Shared Queryable Representation）
- **不変条件の堅持**: Task-Blind Content Encoder $h_{\text{content}} = f(\text{content})$ を維持し、タスク情報や演算引数のエンコーダへの漏洩を構造的に排除する。
- **事前学習／マルチタスク学習**: Stable Core は、複数の基本操作（または自己教師あり・対照学習目的）を通じて、各位置・コンテンツが疎なアテンションで問い合わせ可能な「クエリ可能潜在空間」として事前構築する。

### 5.2 異種小型プリミティブ群（Heterogeneous Compact Primitive Classes）
- すべてのプリミティブを同一の単純 MLP や同一の標準アテンションに固定しない。
- プリミティブは **primitive-scale（$\approx$ 18k〜30k パラメータ）** を厳格に保ちつつ、演算の数学的性質に応じた最小限の構造的帰納バイアス（例: モジュラ相対位置バイアス、キー値マッチング機構など）を備えた数種類の **Primitive Family Class** として設計・登録する。

### 5.3 判定基準の恒久改定（Baseline-Relative None Evaluation）
- 今後の全評価ゲートにおいて、硬直的な一律 `None <= 0.30` を廃止し、タスクの組合せ論的自然ベースラインに基づく $\text{None} \le B_{\text{natural}} + 0.05$ を正式基準とする。

## 6. 旧 A1-R006 の処遇勧告

### 勧告: **旧 A1-R006 を廃止・代替（SUPERSEDED）し、新タスクシーケンスへ移行**

- **理由**:
  1. 旧 `A1-R006`（およびそれに続くタスク群）は、初期の「pointwise low-rank additive primitive」や「未検証の共有表現」を前提に策定されていた。
  2. A1-R005E 診断によって確立された **「Branch B: 共有クエリ可能表現空間」** および **「異種小型クロスアテンション・プリミティブ」** は、旧設計の前提を根底から更新した。
  3. したがって、旧 A1-R006 をそのまま再開することは工学的・学術的に無意味であり、Branch B に立脚した新仕様へ代替（Supersede）することが最も整合的である。
- **次期タスク群の提案（Phase A.1 Post-Diagnostic / Phase A.2）**:
  - **A1-P001**: 共有クエリ可能エンコーダと異種プリミティブバンク（SELECT, COUNT, BIND, SHIFT）の正式なプロダクション統合。
  - **A1-P002**: オラクル選択による4演算の疎実行パイプラインの確立（非選択プリミティブの Forward ゼロ呼出し保証）。
  - **A1-P003**: プリミティブ合成（Composition: 例 SHIFT $\to$ SELECT）の因果的検証。
  - **A1-P004**: Plastic Workspace による未知演算の残差学習検証。

## 7. 未解決のリスクと現時点で未証明の事項

本診断は「表現共有の実現可能性」と「小型プリミティブでの因果的計算可能性」を証明したが、APC の全体像に対しては以下の事項が未証明・リスクとして残されている：

1. **学習済みルータ（Learned Routing）**:
   - 本診断はすべてオラクル呼び出し（Oracle Selection）で実施された。タスク指示 $z_{\text{task}}$ から正しいプリミティブおよび引数を自律的に選択する学習ルータの精度と安定性は未検証である。
2. **連続学習とカタストロフィック忘却**:
   - 新しい演算が登場した際に、Stable Core を凍結したまま Plastic Workspace で残差適応し、それを新たな小型プリミティブとして蒸留・統合（Consolidation）するライフサイクルは次期フェーズの主たる検証対象である。
3. **合成（Composition）の連鎖安定性**:
   - 複数の小型プリミティブを多段に直列実行した際、表現の歪みが生じないかどうかの検証が必要である。
