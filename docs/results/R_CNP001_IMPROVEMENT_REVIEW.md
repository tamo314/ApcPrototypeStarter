# R-CNP-001 改善案レビュー

日付: 2026-09-22 / ADR-0201 / `ARTIFACT_REVIEW_COMPLETE_STOP_PRESERVED`

## 結論

推奨する順序は、**評価契約と親の適格性の明確化 → 学習順序・提示回数の対照 →
旧条件の出力保持制約 → 修正版親からの独立確認**である。rank、層数、更新数の増加を
最初の対策にしない。親の再学習だけで今回の忘却が解消するとも考えない。

本レビューは保存metricsの算術再集計とコードの整数index解析のみ。model forward、
新規研究データ生成、optimizer update、候補採択、sealed accessは0。
R-CNP-001のFAIL、v1のG3 STOPを保持する。以下は改善提案で、実装・実験の実行登録ではない。

根拠: [結果報告](R_CNP001_RESULT.md)、[機械可読再集計](R_CNP001_IMPROVEMENT_AUDIT.json)、
[修正契約](../exec-plans/active/CNP_ADAPTATION_REPAIR_V2.md)。
入力は`runs/cnp_repair/r001/rcnp001_fixed_parent1/metrics.jsonl`。

## 1. 既存証拠から分かったこと

以下は各120セル、5 seedでの**セル件数の平均**。品質はBA≥0.95かつ集合F1≥0.90、
保持は候補F1−親F1≥−0.01。

| 対象 | 親の品質失敗 | 修正後の品質失敗 | 親合格→候補不合格 | 親不合格→候補合格 | 保持失敗 |
|---|---:|---:|---:|---:|---:|
| new | 96.6 | 74.6 | 6.0 | 28.0 | 14.0 |
| old | 19.0 | 58.0 | 45.0 | 6.0 | 60.6 |

- **親の不足と適応の破壊を分ける。** 旧親は15–23セル/seedで既に品質未達。
  これだけを適応による忘却として数えない。一方、新たに旧45セルを平均で落とし、
  old集約F1も−0.028033なので、問題を親の不足だけに帰属することもできない。
  親の不合格はadapterで修復不可能という証明ではない。
- **新条件ではBAが主な不足。** 修正後のnew BA未達は69.6セル、F1未達は36.0セル/seed。
  件数には重複があり、和を総失敗セル数としない。BAのN/Aはnew/oldとも0。
  newの品質失敗は長さ8で93/120、長さ16で92/120（5 seed合計）で、短い集合だけの問題ではない。
- **保持劣化は局在しきっていない。** 全ての長さ・閾値群でoldの平均セルF1差は負。
  閾値0.50では−0.040952、0.80では−0.027975、1.10では−0.014980。
  一つの閾値だけを調整する対策には根拠が足りない。

### 学習スケジュールの偏り

`repair_diagnostic._train_candidate`はnew/replayの双方を
`(step*16+offset)%1536`で取り出す。修正版replay選定も返却順はquery×threshold順である。
bufferを層化したことは、各batchや全256更新の提示回数が均等になったことを意味しない。

| 対象 | 256更新での提示回数 | 終端batch |
|---|---|---|
| newのquery 0–7 | 576, 576, 576, 576, 576, 448, 384, 384 | query 5、threshold 0.50のみ |
| 修正版replayのquery 0–63 | 0–41は各72、42は64、43–63は各48 | query 42、threshold 0.50/0.80 |

newでは同一queryが12更新、同一query×thresholdが4更新続く。
replayは同じqueryに連続して触れ、先頭128 stratumは各24回、残り64は各16回提示する。
これは**確定した提示偏り**である。その偏りが性能低下を起こしたという因果効果は未測定。
new/replayは別query panelなので、同名index間の成績相関だけではこの効果を検証できない。

### 判定・記録の問題

1. 過去の結果文の「new F1最小値0.918274でfloor未達」は誤記。
   0.918274は集約F1基準0.90を上回る。new BA最小値0.927348は0.95未満であり、
   各seedのnew品質セル失敗も残るため、STOPは変わらない。
2. R-CNP-001実装はnewにも親比F1低下≤0.01を要求する。契約の保持対象はoldであり、
   newの品質floorとnewへの追加保持制約を今後は明確に区別する。
   追加条件を外した仮定でも今回のnew品質ゲートは5/5 FAILで、採否は変わらない。
   保存gateを再定義して書き換えない。
3. `condition_key`をセルのdomainとする実装では、各query×threshold×lengthは12または13集合。
   長さ1のセルでは一集合のF1変化が1/13≈0.0769になり得て、許容低下0.01より粗い。
   設計のcondition domainと個別queryの区別、セル件数、N/A処理を次契約で明示する。
   今回の失敗を少数例だけのせいと断定せず、閾値を下げたり事後集約で救済したりしない。
   保存metricsには正負例数・TP/TN/FP/FN・集合別値がなく、誤差の向きやCIは復元できない。

## 2. 優先する改善案

| 優先 | 改善案 | 検証したいこと | 実施時の制約 |
|---|---|---|---|
| 0 | セルの定義、親の品質、品質/保持の別判定、件数・混同行列・集合別値の保存 | 親からの継承失敗と適応で生じた劣化を区別できるか | 閾値維持。既開封panelは開発証拠に限定。親の適格性は独立確認で判定 |
| 1 | query×thresholdをbatch間に分散し、提示回数の偏りを減らす | 連続した条件更新や終端偏りが忘却と汎化不足に寄与するか | 同じbuffer・adapter・loss・new16/replay16・256更新で比較 |
| 2 | replay上で凍結親の出力を保つ補助損失 | 正解BCEだけでは防げない旧入力の出力変化を抑えられるか | replayの既存教師BCEを残す。親の誤りを固定する危険を測る |
| 3 | 初期学習から集合等重みlossを使い、適格な親から再確認 | 修正版全体としてH-CNP1とH-CNP2が成立するか | 新しいsource/開発/確認/適応split、G1→G2→G3、費用・因果対照を事前固定 |

### 最初の有限対照の案

次に実装するなら、まずスケジュールを固定・検査できる仕組みと評価記録を整える。
研究実行を行う場合の候補は、修正版LOCAL上の以下の**三方式**。

- A: 現在の条件順・提示回数を、独立開発panelで再現。
- B: Aと全く同じrecord別提示回数を維持し、順序だけを分散。
- C: Bと同じ分散規則のもと、query×threshold別の提示回数を可能な限り均等化。

A→Bは順序効果、B→Cは提示配分変更の追加効果を調べる対照とし、相互作用まで独立に
同定したとはしない。new/replay合わせた提示数8,192、各側4,096、unique record各1,536を
維持する。4,096はnewの24 stratumやreplayの192 stratumで割り切れないため、
「完全均等」とはせず、各stratumの差を1以内（new170/171、replay21/22）に固定する。
余りの配分とrecordの選定・順序はラベルを使わない登録seedで決め、結果を見て変えない。
同じ乱数初期化、親、panel、最終256step判定を方式間で対応づける。

5親で行う場合は3×5×256=3,840 updatesが上限案。R-CNP-001の保存結果を新splitのAの
代わりにしない。この見積もりは実行認可ではなく、split/seed・時間/VRAM/RAM上限・
判定条件を登録した実行契約が別途必要。最終評価前にレシピを固定し、shadowでの
checkpoint選びや成功seedだけの採用をしない。両ゲートに届かなければSTOPを記録する。

### 保持制約と親の再学習

優先2の一案は、集合等重みのnew/replay BCEに、replay上の親・候補logit差の二乗平均を
加えること。係数は開発段階の有限な計画で事前固定し、同じスケジュールの係数0対照と比較する。
親は凍結してstop-gradientを使い、shadowの教師や出力を学習へ使わない。
これは保持を保証するものではなく、親の既存誤りを温存したり新条件の改善を妨げたりし得る。
親forward/出力cache/optimizerを含む時間・容量を会計する。今回は実装していない。

優先3は独立確認の必要条件を整える作業であり、効果が実証済みの治療策ではない。
旧親の品質不足だけでなく、適応後の追加劣化もあるため、親を作り直して同じ偏った
適応を繰り返す案は優先しない。修正版親のH-CNP1を独立確認してからH-CNP2を判定する。
次の方式比較でもFULL_REPLAYとLEARNED_METRICを残す。既存metricの好成績は別panelの
集約値なので、R-CNP-001における勝利として転用しない。

rank増加、学習延長、new/replay比率変更、複数修正の一括投入は現時点で効果の根拠がない。
将来必要なら一つずつ固定対照で検討する。既存のloss節目ログは異なるbatchの値なので、
収束・過学習・容量不足の診断に用いない。
