## ADR-0025 — H2a passes: content encoding is made structurally (not merely empirically) task-blind via two independent forward passes

**Status:** Accepted

**Decision:** Task A1-R001 (the task-blind content encoder path gate, STOP GATE, H2a, first task of the Phase A.1 Post-Correction Redesign per `docs/exec-plans/active/PHASE_A1_POST_CORRECTION.md`) is recorded as **PASS**. Rather than extending `apc.core.model.DecoderOnlyTransformer.encode_split` (Task A1-005/ADR-0015) -- which reads `task_state`/`content_state` as two renamed views of *one* causal forward pass over `[BOS] [TASK_START] op arg... [TASK_END] input... [SEP]`, so a content position has, by construction, already attended over every task token before it (ADR-0022) -- this task adds a second, independent factorization:

- `apc.core.data.build_task_only_tokens`/`build_content_only_tokens` render a `TaskSpec`/`Example` into two *separate* token sequences (`[BOS] [TASK_START] op arg... [TASK_END]` and `[BOS] input... [SEP]` respectively), neither containing any token from the other's vocabulary range;
- `apc.core.model.DecoderOnlyTransformer.encode_task_content_split(task_ids, content_ids)` calls `encode` twice through the *same* shared weights, once per sequence, returning a new `TaskContentEncoding(task_state, content_state)` -- deliberately not the same type as `EncodedState`, since the two fields here come from different-length sequences and are not interchangeable drop-ins for one another's positions;
- `apc.evaluation.task_blind_content_gate` is the gate: `runs/phase_a1_task_blind_content_gate/report.json`/`summary.json` (config `configs/phase_a1_task_blind_content_gate.yaml`, 5 seeds `0-4`, CPU, git commit `1ed8940`) show, for every seed, all eight `KNOWN_OPERATION_NAMES` covered (128 generated contents/seed, `num_contents_per_operation=16`), zero task-token ids ever present in any content-only token sequence, `content_state` numerically identical across every alternate task spec tested against the same content (`representation_max_absolute_difference=0.0`, exact on CPU, not merely within the predeclared `atol=1e-5`), and `content_state` invariant to batch padding within tolerance (`padding_max_absolute_difference` in `[2.3e-6, 3.1e-6]` across seeds, well under `atol`). All five seeds individually pass; total wall-clock across all five was under 10 seconds.

**Reason:** `docs/design-docs/CAUSAL_PRIMITIVE_EXECUTION.md` section 4 states the required invariant (`h_content(x, t1) == h_content(x, t2)`) is "stronger than a leakage probe" -- an empirical probe on a trained model (A1-C005's approach to a different question) can only ever show "no leakage observed on tested examples," never "leakage is impossible." Running `encode` over a content-only sequence that contains no task token at all makes leakage structurally impossible for *any* weights, trained or not: there is no computational path from a task token to `content_state`, because no task token is ever part of the sequence `content_state` is computed from. This is why the gate deliberately uses freshly-initialized (never trained) models per seed -- the property under test is architectural, not learned, so training first would only cost wall-clock without changing what is measured (`AGENTS.md`: "prefer the smallest implementation that can falsify the current hypothesis"). Per-operation coverage is likewise made structural rather than probabilistic: each of the eight operations gets its own dedicated single-operation `apc.environments.generator.TaskGenerator` (via `build_mixed_operation_generator(operation_names=(name,), ...)`) rather than drawing from one shared eight-operation mixed stream and hoping uniform sampling happens to cover every operation within a small batch (verified empirically during implementation: a single shared draw of 16 examples over 8 operations missed 2 operations entirely at seed 0, which is expected under uniform-random sampling at that batch size, not a defect in the generator).

**Consequence:** Per `docs/exec-plans/active/PHASE_A1_POST_CORRECTION.md`, A1-RM1 (task-blind content path) is satisfied and A1-R002 (decoder leakage control) may proceed -- but only A1-R002 specifically; per `AGENTS.md`'s "Codex workflow," completing A1-R001 does not authorize starting A1-R003 or later. What this task deliberately does *not* provide: any change to decoding/generation (the pre-existing `encode_split`-based full pipeline, and the A1-C004 dense shared-core solver, are both untouched and remain the task-conditioned baseline per `docs/CODEX_TASKS_PHASE_A1_POST_CORRECTION.md` A1-R001 Work item 5); a trained task-blind content representation's actual *capability* to support primitive execution (this gate never trains a model -- whether a *trained* task-blind `content_state` is good enough to support the Correct/Wrong/None causal pattern is A1-R003's parameter-free oracle primitive benchmark, not this one's); and any wiring of `encode_task_content_split` into `apc.core.execution`'s `apply_bank`/`forward_logits` (routing/primitive execution stays out of scope here, matching every earlier Phase A.1 Correction gate's scope discipline -- `apc.primitives`, `apc.plastic`, `apc.consolidation`, and `apc.meta` are not imported anywhere in `apc.evaluation.task_blind_content_gate`). All 682 pre-existing plus new tests pass (`python -m pytest -q`, adding coverage in `tests/test_core_data.py`, `tests/test_core_model.py`, and a new `tests/test_task_blind_content_gate.py`), and `python -m ruff check .` / `python -m mypy src/apc` are both clean.

## ADR-0026 — A1-R002 passes: the causal-mode decode path has no task-conditioned bypass, and a no-primitive/task-blind decoder stays far below the future Correct target

**Status:** Accepted

**Decision:** Task A1-R002 (the decoder leakage control gate, conditional STOP GATE) is recorded as **PASS**.

- **Audit (Work item 1).** `apc.core.execution`'s module docstring records the finding: every causal-mode decode function in the module (`forward_logits`/`generate_greedy_with_capacity`/`evaluate_exact_match_with_capacity`, and A1-C007's oracle-routed siblings) builds its prompt as exactly `(specials.bos,) + example.input_tokens + (specials.sep,)` -- never `apc.core.data.build_prompt_tokens`/`encode_example` with `include_task_spec=True`, and never `example.task_spec` at all -- so no task-segment token id ever reaches `model.encode` through any of them. `tests/test_decoder_leakage.py::test_causal_mode_functions_never_feed_task_tokens_to_encode` verifies this directly (a `model.encode` spy over the bank-routed, oracle-routed, and new no-primitive paths, for real `TaskSpec`-carrying examples, over both a parameterized and a parameter-free operation) by asserting no id in the *initial prompt* falls inside `apc.core.tokens.task_token_id_set` (a helper promoted from A1-R001's own private one, so both gates share one definition of "task token"). Checking only the initial prompt, not every subsequent `model.encode` call in a generation loop, is a deliberate scoping decision: a freshly-initialized (effectively random-output) model can legitimately greedy-generate a token whose id numerically happens to fall in the task-segment range as part of its own answer, which then gets appended and re-encoded on the next step -- that is the model talking to itself, not a task-information bypass, and an initial test draft that checked every call failed on exactly this numerical coincidence (id 30, an argument-value token, appearing only because greedy decoding from a fresh, untrained head can emit anything) before the scoping was narrowed to the prompt alone.
- **Remove task-conditioned bypasses (Work item 2).** The audit found no *live* bypass -- no current caller drives the causal/capacity/oracle-routed functions with a task-spec-carrying input. It did find one *latent* one: `forward_logits(..., use_split_state=True)` computes `content_state` via `model.encode_split(input_ids)`, a single causal pass whose `content_state` is literally `encode(input_ids)` -- if a caller ever passed task-spec-carrying `input_ids` through this branch, `content_state` would have already attended over the task tokens (ADR-0022's finding for `encode_split`, exactly what A1-R001's `encode_task_content_split` two-pass factorization exists to avoid). `use_split_state=True` is exercised only by Task A1-005's own unit tests today, always with content-only input, so there is no code to delete; the fix is a documented restriction (`apc.core.execution`'s module docstring) that the causal *primitive* path must never source `content_state` from `encode_split` for any input that might carry a task segment, rather than a code change to a branch that still serves A1-005's original task_state-routing purpose on content-only input.
- **No-primitive/identity mode (Work item 3).** `apc.core.execution.forward_logits_no_primitive`/`generate_greedy_no_primitive`/`evaluate_exact_match_no_primitive` are new siblings of the bank/oracle-routed functions -- the causal ablation matrix's "None" arm (`docs/design-docs/CAUSAL_PRIMITIVE_EXECUTION.md` section 8) -- with no `bank`/`router`/`workspace` parameter on any of them (`tests/test_decoder_leakage.py::test_no_primitive_functions_never_accept_bank_router_or_workspace`, mirroring A1-C007's `test_oracle_routing_functions_never_accept_a_router`), so primitive execution is structurally unreachable from this path, not merely unused.
- **Evaluate decoder-only task performance (Work item 4).** `apc.evaluation.decoder_leakage_gate` trains one shared core per seed with no task segment ever visible (`apc.evaluation.shared_core_generalization.train_shared_core`, `include_task_spec=False`, identical model/data/training hyperparameters to `configs/phase_a1_shared_core_gate.yaml`'s explicit-task variant for a fair same-family comparison) and evaluates it through `evaluate_exact_match_no_primitive`. `runs/phase_a1_decoder_leakage_gate/report.json`/`summary.json` (config `configs/phase_a1_decoder_leakage_gate.yaml`, 5 seeds `0-4`, RTX 5060 Ti, git commit `6948360`) show: mean overall exact match **0.1401** (stdev 0.0049, min 0.1367, max 0.1484) -- far below both `NO_PRIMITIVE_MATERIAL_CEILING` (0.30, reused from H2b/H2c's own predeclared "None <= 0.30" floor, since neither `docs/CODEX_TASKS_PHASE_A1_POST_CORRECTION.md` A1-R002's acceptance text nor `docs/EXPERIMENT_PLAN_PHASE_A1_POST_CORRECTION.md` -- which has no dedicated hypothesis between H2a and H2b -- spells out a number for "materially below") and the 0.95 future Correct target. Per-operation means: `COPY` 0.754 (expected -- a value-blind identity mapping solvable without any task or primitive information, ADR-0020/ADR-0021), `ACCUMULATE` 0.209 (a mild outlier, consistent with ADR-0021's own note on this same operation), `SHIFT` 0.092, `COMPARE` 0.028, `NEGATE` 0.013, `BIND` 0.012, `COUNT` 0.003, `SELECT` 0.0. `causal_mode_matches_plain_generation` is `true` for every seed: `evaluate_exact_match_no_primitive` and `apc.core.generation.evaluate_exact_match(..., include_task_spec=False)` produce bit-identical exact-match scores and predictions, confirming the newly audited entry point reproduces the pre-existing evaluation path exactly rather than measuring something subtly different.

**Reason:** This is not a new phenomenon to discover -- `apc.evaluation.shared_core_generalization`'s `include_task_spec=False` variant is, by construction, already "train a shared core with no task segment ever visible, evaluate decoder-only exact match," and ADR-0021 already measured it at 0.139 mean overall exact match (5 seeds). This task's own run (0.1401, an independent training run under a fresh git commit and a differently-audited evaluation code path) reproduces that finding closely, which is itself evidence of robustness rather than redundant: it confirms the finding is not an artifact of the specific evaluation function used to measure it (`apc.core.generation.evaluate_exact_match` for ADR-0021 vs. the newly added, structurally primitive-free `apc.core.execution.evaluate_exact_match_no_primitive` here), and the two entry points are shown to agree exactly on the same model/examples rather than merely producing similar-looking aggregate numbers. Training (rather than testing an untrained model, as A1-R001's structural gate did) is necessary here specifically because the claim under test is empirical, not architectural: "no task info reaches the decoder" is proven structurally by the audit, but "therefore a *trained* decoder cannot solve the task anyway" requires actually training one and measuring what it converges to -- an untrained model's near-zero accuracy would not be informative either way.

**Consequence:** Per `docs/exec-plans/active/PHASE_A1_POST_CORRECTION.md`, A1-RM2 (decoder leakage control) is satisfied and A1-R003 (parameter-free oracle primitive benchmark) may proceed -- but only A1-R003 specifically, per `AGENTS.md`'s "Codex workflow." What this task deliberately does *not* provide: any primitive execution wiring, or the "Correct"/"Wrong" arms of the causal ablation matrix (both A1-R003's); and it does not change `forward_logits`'s `use_split_state=True` branch's actual behavior, only documents it as unsuitable for the causal primitive path -- a future task wiring routing into that path (A1-R003 onward) must source `content_state` from `encode` (on content-only ids) or `encode_task_content_split`, never `encode_split`, for any input that might carry a task segment. `docs/AGENTS_PHASE_A1_POST_CORRECTION_ADDENDUM.md`'s "If Correct/Wrong/None are all high, suspect Stable Core or decoder leakage" branch does not apply here, since no primitive-routed "Correct"/"Wrong" condition exists yet to compare against; this gate establishes only that the "None" arm's own future value is trustworthy (not already saturated by a bypass) ahead of A1-R003 adding the other two arms. All 713 pre-existing plus new tests pass (`python -m pytest -q`, adding `tests/test_decoder_leakage.py` and `tests/test_decoder_leakage_gate.py`), and `python -m ruff check .` / `python -m mypy src/apc` are both clean.

## ADR-0027 — A1-R003 passes: parameter-free oracle primitives are causally necessary on top of a pretrained-then-frozen Stable Core

**Status:** Accepted

**Decision:** Task A1-R003 (the parameter-free oracle primitive benchmark, STOP GATE, H2b) is recorded as **PASS**. `apc.evaluation.parameter_free_primitive_gate` implements the gate as: (1) pretrain one `apc.core.model.DecoderOnlyTransformer` per seed task-blind (`apc.evaluation.shared_core_generalization.train_shared_core`, `include_task_spec=False`, restricted to `apc.environments.operations.DETERMINISTIC_OPERATION_NAMES` -- `COPY`/`NEGATE`/`COMPARE`/`ACCUMULATE`), then freeze every one of its parameters (`requires_grad_(False)`); (2) register one `apc.primitives.primitive.Primitive` (rank 8) per operation in a fresh `apc.primitives.bank.PrimitiveBank`, keyed at `apc.environments.task_spec.operation_id(name)` (ADR-0024's convention); (3) train only the primitive bank's parameters, via a new gradient-enabled oracle-routing path this task adds to `apc.core.execution` (`apply_bank_with_oracle_calls_trainable`/`forward_logits_with_oracle_calls_trainable` -- the existing A1-C007 `apply_bank_with_oracle_calls`/`forward_logits_with_oracle_calls` stay exactly as they were, always `torch.no_grad()`-wrapped, and are reused unmodified for evaluation); (4) evaluate the causal ablation matrix's three arms on a large unseen batch via `apc.core.execution.evaluate_exact_match_with_oracle_calls` (Correct: `apc.environments.generator.oracle_call_for_example`'s own correct call; Wrong: a fixed derangement over `operation_names` forcing a different family) and `evaluate_exact_match_no_primitive` (None, A1-R002's own entry point, unmodified).

`runs/phase_a1_parameter_free_primitive_gate/report.json`/`summary.json` (config `configs/phase_a1_parameter_free_primitive_gate.yaml`, 5 seeds `0-4`, RTX 5060 Ti, git commit `0bbb290` -- the A1-R002 commit; this run predates A1-R003's own commit, matching ADR-0026's "6948360" precedent of the run preceding the commit that lands its code) show:

- **Correct** mean **0.9999** (stdev 0.0002, min-over-seeds 0.99951, max 1.0) -- threshold 0.95;
- **Wrong** mean **0.0** (every seed, every operation) -- ceiling 0.30;
- **None** mean **0.2482** (per-seed range 0.2427-0.2514) -- ceiling 0.30;
- **causal gap** (Correct − max(Wrong, None)) mean **0.7517** -- threshold 0.50;
- per-operation Correct means: `COPY` 1.0, `NEGATE` 1.0, `COMPARE` 1.0, `ACCUMULATE` 0.9996 -- no operation is an outlier.

All four `run_parameter_free_primitive_gate_multi_seed` sub-verdicts (`correct_passed`, `wrong_passed`, `none_passed`, `causal_gap_passed`) are `true`, `meets_seed_policy` is `true`, and `passed` is `true`. Total wall-clock across all 5 seeds was 3954s (~66 min) on the RTX 5060 Ti; `core_trainable_param_count` is `0` for every seed (the freeze is verified structurally in the report itself, not merely asserted); `primitive_param_count` is 12288 (4 primitives × rank 8 × 2 × 192, i.e. `a_proj`+`b_proj` only) against `core_param_count` 1795968 -- the trained capacity solving the task is under 0.7% of the frozen core's size.

**Reason:** `docs/CODEX_TASKS_PHASE_A1_POST_CORRECTION.md` A1-R003 leaves "freeze Stable Core" underspecified as to *how* the frozen weights are reached. A core frozen at random initialization was considered and rejected before implementation: `apc.core.model.DecoderOnlyTransformer.decode` is a `LayerNorm`-normalized hidden state dot-producted against tied token embeddings, so a rank-8 primitive residual needs a working content-encoding/decoding scaffold under it to have anything to build on, and `ACCUMULATE`/`COMPARE` specifically need the frozen core's causal self-attention layers to have learned genuine cross-position aggregation (a per-position primitive delta cannot mix across positions by itself) -- an untrained random backbone would make a low Correct score uninterpretable between "primitive incapacity" and "no usable scaffold at all" (`AGENTS.md`'s own "If Correct, Wrong, and None are all low, suspect content representation or primitive capacity" anticipates exactly this ambiguity). Pretraining task-blind (mirroring A1-R002's own `include_task_spec=False` procedure, restricted here to the four-operation pool) gives the core genuine pressure to develop useful representation/aggregation machinery while remaining structurally unable to resolve *which* operation applies (ADR-0017/ADR-0020/ADR-0021's own non-identifiability finding) -- exactly the boundary `AGENTS.md`'s Stable Core role draws ("may provide ... representation transport, decoding infrastructure. It must not ... perform the operation-specific transformation"). The measured result confirms the design was sound rather than merely permissible: `final_core_train_loss` plateaus around 0.16-0.18 (never near zero -- the core alone cannot resolve the ambiguous objective, consistent with `None`'s 0.25 ceiling), while `final_primitive_train_loss` converges to ~3e-5-2e-4 -- the primitives, reading the same frozen, still-ambiguous representation, resolve the task almost perfectly once oracle routing removes the ambiguity for them. `Wrong` landing at exactly 0.0 for every seed and every operation (not merely "materially lower") is the cleanest possible confirmation of the causal ablation matrix's core claim: forcing e.g. `NEGATE`'s trained primitive onto a `COPY`/`COMPARE`/`ACCUMULATE` example produces systematically incorrect output every time, meaning the primitive is actually computing its own specific operation on `h_content`, not merely nudging logits toward a generically-plausible answer. This is the first Phase A.1 Post-Correction task where `AGENTS.md`'s "Correct primitive -> high accuracy, Wrong primitive -> low accuracy, No primitive -> low accuracy" success pattern is demonstrated end to end.

**Consequence:** Per `docs/exec-plans/active/PHASE_A1_POST_CORRECTION.md`, A1-RM3 (parameter-free oracle primitive causality) is satisfied and A1-R004 (argument conditioning module) may proceed -- but only A1-R004 specifically, per `AGENTS.md`'s "Codex workflow" ("completion of one task does not authorize beginning the next task"). What this task deliberately does *not* provide: any parameterized primitive (`SHIFT`/`SELECT`/`COUNT`/`BIND`, gated separately by `required_argument_names` validation in `ParameterFreePrimitiveGateConfig.__post_init__` so a misconfigured pool fails fast rather than silently under-testing A1-R003's own scope); promotion of these trained primitives to a persistent/`STABLE` bank (they are constructed fresh per run, `PrimitiveStatus.CANDIDATE`, and discarded -- no consolidation, no bank reuse across seeds); and no change to the existing no-grad `apply_bank_with_oracle_calls`/`forward_logits_with_oracle_calls` (A1-C007) -- their gradient-enabled `_trainable` siblings are new, additive functions, covered by dedicated regression tests (`tests/test_oracle_routing.py`: numeric equivalence to the no-grad sibling, gradient reaching only the oracle-selected primitive and never an unselected family, structural exclusion of `Router` matching A1-C007's own convention). All 745 pre-existing plus new tests pass (`python -m pytest -q`, adding 6 cases to `tests/test_oracle_routing.py` and 26 in the new `tests/test_parameter_free_primitive_gate.py`), and `python -m ruff check .` / `python -m mypy src/apc` are both clean.

## ADR-0028 — A1-R004 argument conditioning module: keyword-only arguments, modulo-bucketed encoders, two encoder shapes for four typed argument slots

**Status:** Accepted

**Decision:** Task A1-R004 (argument conditioning module, milestone A1-RM4) is implemented as `apc.primitives.conditioning`, a new module, plus one small additive constant in `apc.environments.operations`. It is **not** a STOP GATE and is not itself a seeded benchmark (that is A1-R005's job); its acceptance criteria (`docs/CODEX_TASKS_PHASE_A1_POST_CORRECTION.md` A1-R004: "changing argument changes output," "same family handles >=3 values," "persistent family count unchanged," "invalid/missing arguments tested") are demonstrated at the unit level in the new `tests/test_primitives_conditioning.py` (42 cases) rather than via a multi-seed run/report. Contents:

1. `PARAMETERIZED_OPERATION_NAMES` added to `apc.environments.operations` -- the complement of `DETERMINISTIC_OPERATION_NAMES`, *derived* from `Operation.required_argument_names` rather than hardcoded (`("SELECT", "COUNT", "SHIFT", "BIND")` in registration order) so a future operation with a hidden argument is picked up automatically.
2. `ArgumentEncoder` (abstract `nn.Module`) plus two concrete typed encoders, not four: `IntBucketArgumentEncoder` (one bounded integer -> a learned embedding-table lookup via `value % num_buckets`) covers `SHIFT.amount`, `COUNT.target`, and `BIND.query_key` alike -- all three are, at the representation level, "one integer picked from a bounded range," even though `SHIFT.amount` (a rotation distance) and `COUNT.target`/`BIND.query_key` (content-vocabulary tokens, `apc.environments.vocab`) are semantically distinct concepts and therefore get their *own* embedding-table instances (never shared weights across those three). `IndexSetArgumentEncoder` (the mean of learned per-position embeddings over a variable-size index subset, each position also taken modulo the encoder's own capacity) covers `SELECT.indices` -- reusing `docs/DECISIONS.md` ADR-0023's finding that `SELECT`'s real hidden parameter is a subset of positions, never a single scalar index, so a single-integer encoder cannot represent it. `default_argument_encoder(operation, ...)` is what actually gives each of the four operations its own named, appropriately-sized instance, so the module's public surface still presents as "one typed encoder per argument" per the task text, without four near-identical encoder classes.
3. `ConditionedPrimitive(Primitive)` implements `docs/design-docs/CAUSAL_PRIMITIVE_EXECUTION.md` section 6's minimal conditioning formula (`e_a = encoder(argument); u = A_i(h); c = C_i(e_a); delta = B_i(phi(u + c)); out = h + gate * delta`) directly on top of the existing `a_proj`/`b_proj` (`A_i`/`B_i`, Task 004/A1-R003), adding one linear map `c_proj` (`C_i`) and reusing `apc.core.model.DecoderOnlyTransformer`'s own `GELU` for `phi`. `a_proj`/`b_proj`/`c_proj`/`argument_encoder` are all shared across every argument value the family is ever called with -- there is no per-value parameter, satisfying "shared family weights across values" by construction rather than by a runtime check. `build_conditioned_primitive(primitive_id, operation, config, ...)` mints one instance per family, keyed at the caller-supplied `primitive_id` (intended usage: `apc.environments.task_spec.operation_id(operation)`, ADR-0024's convention, verified in `tests/test_primitives_conditioning.py::test_build_conditioned_primitive_uses_the_operations_own_argument_name`), and subclasses `Primitive` (not a parallel type) specifically so a future `PrimitiveBank` can hold it via the existing `add_primitive`/`get` path (`PrimitiveBank.get`'s `isinstance(primitive, Primitive)` assertion) with no `apc.primitives.bank` change required.

**Reason:** Two design questions were not settled by `docs/design-docs/PARAMETERIZED_PRIMITIVE_CALLS.md`/`CAUSAL_PRIMITIVE_EXECUTION.md` and needed a concrete answer before implementation:

*Invalid vs. missing arguments (A1-R004's own "invalid/missing arguments tested" criterion names two different failure modes that call for two different behaviors).* An "invalid" argument -- syntactically well-typed but outside a family's declared range, e.g. `SHIFT.amount = 500` against a 32-bucket table -- must not raise, because A1-R005's own "correct family + wrong argument" causal control (H2c, `docs/EXPERIMENT_PLAN_PHASE_A1_POST_CORRECTION.md` section 4) needs to be able to *construct and run* exactly such a call, not have it rejected. Both encoders therefore wrap any out-of-range integer via `torch.remainder(value, capacity)` rather than validating a range. A "missing" argument -- the caller forgot to supply one at all -- is the opposite case and should fail loudly, so `ConditionedPrimitive.forward`'s `argument_values` parameter is keyword-only with no default. This was chosen specifically because `apc.core.execution.apply_bank`/`_route_and_apply_oracle_calls` invoke every routed bank primitive as `primitive(selected_hidden)` -- a single positional argument, no keywords, gate applied outside the call -- so if `argument_values` were an ordinary optional parameter with a default, a `ConditionedPrimitive` accidentally placed in a bank routed through today's argument-blind execution path would silently receive that default (e.g. `None`) on every call instead of failing: exactly the "argument present in the call but ignored by the neural transform" AGENTS.md's parameterized-primitives rule forbids, except silent rather than caught by any test. Keyword-only closes this structurally: any accidental use of `ConditionedPrimitive` through the existing A1-C007/A1-R003 call sites raises `TypeError` immediately rather than quietly executing an argument-blind transform. `forward_from_calls(h, calls)` is the safe entry point for the intended `PrimitiveCall`-carrying caller (A1-R005); it raises `KeyError` if a given call's `operation` does not carry this primitive's own `argument_name` at all -- a mismatched call, not merely an out-of-range value.

*Two encoder classes vs. four.* A four-class design (one class literally named after each argument) was considered and rejected: `SHIFT.amount`, `COUNT.target`, and `BIND.query_key` share an identical representation shape (one bounded integer -> embedding-table row), so four classes would mean three of them differ only in constructor arguments (`num_buckets`) -- duplicated code with no representational benefit, contrary to `AGENTS.md`'s "do not introduce ... unnecessarily general function signatures" and "keep research code readable." `default_argument_encoder` resolves the tension: it is the thing that is actually keyed one-per-operation-name (four branches, four independently-sized instances with no shared weights, even between `COUNT` and `BIND` which share a value domain but not a learned meaning), while the underlying implementation stays at two classes matching the two genuinely distinct raw shapes (`docs/design-docs/PARAMETERIZED_PRIMITIVE_CALLS.md` never specifies argument *encoding* beyond "possible implementations: ... learned argument embeddings," leaving this open).

**Consequence:** Per `docs/exec-plans/active/PHASE_A1_POST_CORRECTION.md`, A1-RM4 (argument-conditioned neural primitives: "one family handles multiple arguments without family growth") is satisfied and A1-R005 (parameterized oracle primitive benchmark, STOP GATE, H2c) may proceed -- but only A1-R005 specifically. What this task deliberately does *not* provide, left for A1-R005: wiring `PrimitiveCall.arguments` through `apc.core.execution`'s oracle-routing entry points (`apply_bank_with_oracle_calls*`/`forward_logits_with_oracle_calls*` still call every bank primitive as `primitive(selected_hidden)`, which now raises `TypeError` for a `ConditionedPrimitive` rather than silently mishandling it -- a deliberate fail-loud gap, not an oversight); any training of a `ConditionedPrimitive`; measuring Correct/Wrong-family/Wrong-argument/None; and promotion to a persistent `STABLE` bank or consolidation. All 787 tests pass (`python -m pytest -q`: 745 pre-existing + 42 new in `tests/test_primitives_conditioning.py`), and `python -m ruff check .` / `python -m mypy src/apc` are both clean.

## ADR-0029 — A1-R005 STOP GATE fails: argument-conditioned primitives are family-selective but not argument-selective, and multi-token exact match ceilings SHIFT/SELECT

**Status:** Accepted

**Decision:** Task A1-R005 (the parameterized oracle primitive benchmark, STOP GATE, H2c) is recorded as **FAIL**. `apc.evaluation.parameterized_primitive_gate` implements the gate exactly as A1-R003's own precedent (ADR-0027): pretrain-then-freeze one task-blind `DecoderOnlyTransformer` per seed (`include_task_spec=False`, restricted to `apc.environments.operations.PARAMETERIZED_OPERATION_NAMES` -- `SHIFT`/`SELECT`/`COUNT`/`BIND`), register one `apc.primitives.conditioning.ConditionedPrimitive` (rank 8) per operation in a fresh `PrimitiveBank`, train only the primitive bank via oracle-forced routing that now threads each example's own argument through (`apc.core.execution`'s A1-R005 dispatch addition to `_route_and_apply_oracle_calls`, routing a `ConditionedPrimitive` through `forward_from_calls` instead of the old argument-blind call), and evaluate the four-arm causal ablation matrix (`docs/design-docs/CAUSAL_PRIMITIVE_EXECUTION.md` section 8) on a large unseen batch: **Correct** (correct family + correct argument), **Wrong argument** (correct family + a deterministic "+1 modulo the argument's own valid domain" substitution), **Wrong family** (a fixed derangement, forced with a fixed default argument), **None** (`apc.core.execution.evaluate_exact_match_no_primitive`, unchanged from A1-R002).

`runs/phase_a1_parameterized_primitive_gate/report.json`/`summary.json` (config `configs/phase_a1_parameterized_primitive_gate.yaml`, 5 seeds `0-4`, RTX 5060 Ti, git commit `4edc4c0` -- the A1-R004 commit; this run predates A1-R005's own commit, matching ADR-0026/ADR-0027's precedent of the run preceding the commit that lands its code) show, against the cross-seed mean:

| Arm | Mean | Required |
|---|---|---|
| Correct | **0.308** (stdev 0.017, min 0.290, max 0.328) | >= 0.90 |
| Wrong argument | 0.255 | <= 0.30 |
| Wrong family | 0.028 | <= 0.30 |
| None | 0.143 | <= 0.30 |
| Causal gap (Correct - max of the three) | **0.053** | >= 0.50 |

`correct_passed=false`, `causal_gap_passed=false`; `wrong_argument_passed`/`wrong_family_passed`/`none_passed`/`family_count_passed` are all trivially `true` (every control arm clears its ceiling only because `Correct` itself is far below target, not because the gate demonstrates the intended causal pattern). Per-operation mean Correct: `COUNT` 0.595, `BIND` 0.420, `SHIFT` 0.161, `SELECT` 0.047.

**Reason:** Two distinct findings, both visible directly in the numbers above, together explain the failure without requiring further instrumentation:

1. **Family selection is strongly causal; argument selection within a family is barely causal.** `Wrong family` (0.028) collapsing far below `Correct` (0.308) reproduces A1-R003's own core finding (ADR-0027: forcing the wrong computation family produces systematically wrong output) -- the frozen core's `h_content` genuinely carries family-selective computation once a `ConditionedPrimitive` reads it. But `Wrong argument` (0.255) sits only ~0.05 below `Correct` (0.308), not "materially lower" by any reading of H2c's own text -- i.e. once the *correct family* is selected, substituting a wrong-but-valid argument barely changes the outcome. This means `ConditionedPrimitive`'s `c_proj`/`argument_encoder` path (Task A1-R004, ADR-0028) is not, at this training budget, learning to make the residual actually depend on the argument value in a way that changes the *output tokens* -- exactly the failure mode `AGENTS.md`'s "arguments that are stored or logged but ignored by the neural transform do not count as parameterized execution" warns about, now observed empirically rather than merely guarded against structurally (Task A1-R004's `forward_from_calls`/keyword-only design prevents the argument from being *silently dropped*, but does not by itself guarantee it is *learned*).

2. **Per-operation Correct tracks output length, not operation difficulty in isolation.** `COUNT` (single output token, 0.595) and `BIND` (single output token, 0.420) reach far higher exact match than `SHIFT` (full-length rotation, up to 10 output tokens, 0.161) or `SELECT` (variable-length ordered subset, up to 5 output tokens, 0.047). Exact-match scoring requires every output position correct simultaneously, so if per-token accuracy were even roughly comparable across operations, multi-token outputs would show a compounding exact-match penalty (`p^n` for `n` positions) that single-token outputs never pay. This is consistent with, and does not require rejecting, finding 1: `SHIFT`/`SELECT` additionally need the argument to correctly select *which* rotation/subset at *every* output position, so their `Correct` score is suppressed by both the weak argument-selectivity of finding 1 and the multi-token compounding of finding 2 at once, while `COUNT`/`BIND`'s single-token output only pays the former cost.

Reused training budget from A1-R003 (`core_train.steps=30000`, `primitive_train.steps=10000`, `primitive_rank=8`, matching `configs/phase_a1_parameter_free_primitive_gate.yaml` exactly) was a deliberate choice, not an oversight: `AGENTS.md`'s engineering principles ask for "the smallest implementation that can falsify the current hypothesis," and A1-R003 (H2b, parameter-free primitives on the same frozen-core strategy) already demonstrated that budget is sufficient to reach Correct >= 0.999 for `COPY`/`NEGATE`/`COMPARE`/`ACCUMULATE`. Reusing it unchanged isolates *what changed* (argument conditioning, `ConditionedPrimitive`'s extra `c_proj`/`argument_encoder` capacity, and a harder operation pool including full-sequence-length outputs) as the only variable between a passing gate (A1-R003) and this failing one, rather than confounding the comparison with a simultaneously enlarged budget.

**Consequence:** Per `AGENTS.md`'s STOP GATE discipline, dependent work halts here: A1-R006 (unified oracle primitive benchmark, which composes A1-R003's and A1-R005's own primitive families) and everything after it in `docs/CODEX_TASKS_PHASE_A1_POST_CORRECTION.md` remain blocked until this gate passes. Per `AGENTS.md`'s "Do not hide negative results by increasing model size prematurely, expanding data without a specific hypothesis, ... or adding a larger router": no larger `primitive_rank`, longer `primitive_train.steps`, nor architecture change has been applied in response to this result -- the config, code, and this ADR are the STOP GATE record, and any retry needs its own explicit, hypothesis-driven task rather than a silent parameter bump. Candidate hypotheses for a future A1-R005 retry task, none executed here: (a) argument-selectivity may need more `primitive_train` steps specifically (the argument-conditioning path is strictly newer/less-exercised machinery than `a_proj`/`b_proj` alone), (b) `arg_dim`/`c_proj` capacity relative to `rank=8` may be a bottleneck for `SHIFT`'s/`SELECT`'s position-indexed arguments specifically (both route through the same rank-8 residual `COUNT`/`BIND` use, despite needing to select among as many as `max_sequence_length` distinct rotations/subsets rather than `vocab_size` content values), (c) `SHIFT`/`SELECT`'s multi-token output may warrant measuring per-token accuracy alongside exact match to separate "argument not learned" from "compounding exact-match penalty" more cleanly than the aggregate numbers above can alone. What this task does *not* put in doubt: A1-R004's own acceptance (ADR-0028, unit-level: changing an argument does change a freshly-perturbed `ConditionedPrimitive`'s raw output in isolation) -- the gap found here is that this capacity is not learned to be *task-relevant* at this training budget/operation pool, not that the module cannot represent argument-dependence at all. `apc.core.execution`'s A1-R005 dispatch wiring (`_route_and_apply_oracle_calls` routing a `ConditionedPrimitive` through `forward_from_calls`) is exercised correctly by this run (`family_count_passed=true` every seed, `bank_size=4` throughout, matching "family count stays constant across argument values") and by `tests/test_oracle_routing.py`'s new dispatch tests -- the wiring is not itself implicated by this failure. All 825 tests pass (`python -m pytest -q`: adding 34 in the new `tests/test_parameterized_primitive_gate.py` and 6 in `tests/test_oracle_routing.py`'s new `ConditionedPrimitive` dispatch section; net of removing one long-orphaned Task 012 test, see below), and `python -m ruff check .` / `python -m mypy src/apc` are both clean.

## ADR-0031 — A1-R005D-002 audit: `SELECT`'s mean-pooled index encoder is a structural, weight-independent collision; `SHIFT`/`COUNT`/`BIND` are injective on their real legal domains

**Status:** Accepted

**Decision:** Task A1-R005D-002 (`docs/CODEX_TASKS_A1_R005_RETRY.md`, "argument encoder integrity audit ... detect representation collisions before training") is recorded as **done**, with the SELECT half of its own acceptance criteria resolving to **non-injective, STOP GATE in force**. New module `apc.primitives.argument_encoder_audit` (`scripts/r005d002_audit_argument_encoders.py`) audits every `apc.primitives.conditioning.default_argument_encoder` instance without constructing, training, or loading any `DecoderOnlyTransformer` -- pure forward passes through freshly constructed `ArgumentEncoder`s.

- **`SELECT.indices` (`IndexSetArgumentEncoder`, mean-pooled over per-position embeddings).** `audit_select_order_sensitivity` runs 5 declared permutation pairs -- the task's own `[1, 3]` vs `[3, 1]` example, a longer reversal, and two repeated-index permutations (`(1, 1, 3)` vs `(1, 3, 1)`/`(3, 1, 1)`, legal per `apc.environments.primitive_call.PrimitiveCall.__post_init__`'s lack of any uniqueness/order constraint on `indices`, and per `apc.environments.operations.SelectOp.apply` executing a repeated index without error even though `SelectOp.sample_params` itself never produces one) -- across 3 independently-seeded encoder instances (`runs/a1_r005d_002_argument_encoder_audit/report.json`). Every one of the 5 pairs collides in every one of the 3 seeds (`max_absolute_difference` at or below float32 rounding noise, ~1.2e-7, not exactly `0.0`, since summing the same embedding rows in a different order is float-non-associative -- `tests/test_primitives_conditioning.py::test_index_set_encoder_is_order_invariant`'s own `atol=1e-6` precedent). This is expected, not merely observed: mean is commutative, so the collision is a property of the pooling operator itself, true for *any* embedding weights, not a coincidence of these particular seeds -- the multi-seed sweep demonstrates rather than merely asserts that weight-independence. 3 declared distinct-same-length index-set pairs (non-permutations, e.g. `(0, 1, 2)` vs `(3, 4, 5)`) show **no** collision at any checked seed, confirming the failure is specifically about order/multiplicity, not a general collapse of the representation.
- **`SHIFT.amount`/`COUNT.target`/`BIND.query_key` (`IntBucketArgumentEncoder`, modulo-bucketed embedding lookup).** `audit_int_bucket_encoder` checks every pair of *distinct* values in each operation's real legal domain -- `range(10)` for `SHIFT.amount` (`apc.environments.operations.ShiftOp.sample_params` draws from `range(len(sequence))`, and `apc.environments.generator.TaskGenerator`'s default `sequence_length_range=(6, 10)` bounds `len(sequence)` at 10 inclusive per `_valid_lengths_for_chain`'s `range(min_len, max_len + 1)` -- the same upper bound `apc.environments.task_spec.default_argument_value_span` already treats as authoritative for this domain), `range(10)` for `COUNT.target`/`BIND.query_key` (`apc.environments.vocab.DEFAULT_VOCAB_SIZE`) -- against `default_argument_encoder`'s current `num_buckets` (32 for `SHIFT`, matching `DEFAULT_MAX_SEQUENCE_LENGTH`; 10 for `COUNT`/`BIND`, matching `vocab_size`). All three are **injective on their real legal domain**: zero colliding pairs at any of the 100 (`SHIFT`) or 45+45 (`COUNT`/`BIND`) distinct-value pairs checked. A deliberately out-of-domain probe (`max(legal_domain) + num_buckets`, e.g. `41` for `SHIFT`) confirms the wraparound path is reachable and lands exactly on the largest legal value (`max_absolute_difference == 0.0`, an exact embedding-table row match) -- the intentional aliasing `docs/DECISIONS.md` ADR-0028 designed for A1-R005's "correct family + wrong argument" causal control, not an accidental in-domain collision. A regression test (`test_int_bucket_audit_catches_a_deliberately_undersized_bucket_table`, a `num_buckets=5` encoder against the same `range(10)` domain) confirms the audit *would* catch a real misconfiguration rather than trivially passing regardless of input.

**Reason:** `docs/AGENTS_A1_R005_RETRY_ADDENDUM.md`'s "SELECT rule" already stated the hypothesis -- "a commutative pooling representation such as mean/sum is invalid for an ordered index sequence unless an explicit experiment proves otherwise" -- and `tests/test_primitives_conditioning.py::test_index_set_encoder_is_order_invariant` already demonstrated the underlying fact at the unit level when A1-R004 landed (written then as expected/acceptable behavior, before this retry's stricter order-preservation rule existed). This task's contribution is not discovering a new fact but (a) connecting that fact explicitly to the SELECT/`argument_effect_rate` findings already on record (ADR-0029's `SELECT` Correct 0.047 lowest of all four operations; ADR-0030's re-analysis found `SELECT`'s wrong-argument control effectful on 99.2% of examples yet the raw Correct-vs-Wrong-argument gap only 0.005 -- entirely consistent with an encoder that structurally cannot represent *which* subset-with-order was requested, on top of ADR-0029's own multi-token exact-match compounding explanation) and (b) making the STOP GATE enforceable rather than only documented: `require_order_preserving_select_encoder` actually runs an encoder against `[1, 3]`/`[3, 1]` and raises `NonInjectiveSelectEncoderError` if they collide -- behavior-based, not an `isinstance` check, so it also catches a future replacement encoder that happens to still be order-insensitive. This guard is deliberately **not** wired into `apc.primitives.conditioning.build_conditioned_primitive`/`default_argument_encoder` themselves: those are A1-R004's already-accepted surface (ADR-0028), still exercised unchanged by `tests/test_primitives_conditioning.py`'s existing acceptance tests, and A1-R005D-002's own scope is audit-and-gate-future-training, not replacing the encoder (that is explicitly A1-R005D-003's job, itself conditioned on "skip only if D-002 proves current representation sufficient" -- resolved here as **not sufficient**).

**Consequence:** Per `docs/exec-plans/active/A1_R005_RETRY.md`, R005-M2 (argument encoder integrity) is satisfied with a **non-injective** verdict for `SELECT`, and the STOP GATE named in A1-R005D-002's own task text is now in force and enforceable: *no future task may train `SELECT` through `apc.primitives.conditioning.IndexSetArgumentEncoder`* without first calling `apc.primitives.argument_encoder_audit.require_order_preserving_select_encoder` (or otherwise replacing the encoder) -- A1-R005D-003 (order-preserving SELECT argument encoder) is **not skipped** and remains required before any SELECT counterfactual/gate task (D-004 onward, when it reaches SELECT) trains against real order-sensitive supervision. `SHIFT`/`COUNT`/`BIND` carry no such block: their current `IntBucketArgumentEncoder` instances are confirmed injective on Phase A.1's actual generator/vocab defaults, so D-004's COUNT counterfactual gate may proceed without an encoder change. ## ADR-0032 — A1-R005D-003: order-preserving `SELECT` argument encoder replaces mean pooling as the production default

**Status:** Accepted

**Decision:** Task A1-R005D-003 (`docs/CODEX_TASKS_A1_R005_RETRY.md`, "replace mean pooling if D-002 confirms order loss") is implemented. ADR-0031 resolved D-003's own "skip only if D-002 proves current representation sufficient" condition as **not sufficient** (SELECT's mean-pooled `IndexSetArgumentEncoder` collides on every permutation pair in every seed), so this task is not skipped.

New class `apc.primitives.conditioning.OrderPreservingIndexSetArgumentEncoder` (`ArgumentEncoder` subclass, same module) implements the task's own "preferred minimal form" directly: per selected position `i` (0-indexed by its slot *within the argument list*), `token_i = index_embedding[value_i mod max_positions] + position_embedding[i mod max_positions]`; the resulting `[batch, seq_len, arg_dim]` token sequence passes through one `nn.TransformerEncoderLayer` (`nhead=1`, `dim_feedforward=2*arg_dim`, `dropout=0.0`, `batch_first=True`) with a `src_key_padding_mask` for batches of unequal-length index lists, then a masked mean pool over valid (non-pad) positions produces the fixed-size `[batch, arg_dim]` embedding. `default_argument_encoder("SELECT", ...)` (`apc.primitives.conditioning`) now returns this encoder instead of `IndexSetArgumentEncoder`; `build_conditioned_primitive`/`ConditionedPrimitive` are unchanged (they already treat `argument_encoder` as an opaque `ArgumentEncoder`, so no other code needed to change). `IndexSetArgumentEncoder` itself is left exactly as A1-R004 built it -- still directly constructible, still exercised by its own existing tests -- just no longer reachable through the default factory.

Why a position embedding alone does not suffice, and a nonlinear mixing step is required: adding `position_embedding[i]` to `index_embedding[value_i]` and then reducing with any *linear, permutation-symmetric* operator (sum or mean) still cannot distinguish an assignment of values to slots from a different one, because such a reduction is exactly `(sum of index embeddings) + (sum of position embeddings)` -- both sums range over the same two multisets (the selected values, and the positions `0..n-1`) regardless of which value was paired with which position. `[1, 3]` and `[3, 1]` therefore still collide under "embed + positional-add + mean." The self-attention layer is the part that actually breaks this: its query/key dot products are quadratic in the per-slot vectors, so the attention weights -- and hence the pre-pooling encoded sequence each slot produces -- depend on which index occupies which slot, not merely on the multiset of `(index, position)` pairs present. `dropout=0.0` (applied to both the attention weights and the two post-attention/post-feedforward dropout layers `nn.TransformerEncoderLayer` wires internally from the same constructor argument) makes the forward pass deterministic regardless of `self.training`, rather than relying on callers to remember `.eval()`.

New tests in `tests/test_primitives_conditioning.py` (14 cases) cover the task's own acceptance criteria directly: `[1, 3]` vs `[3, 1]` distinct (single seed and across 5 independent seeds, matching ADR-0031's own multi-seed precedent for the collision it found), repeated-index permutations distinct, variable-length index sets in one batched call, a short row's output is bit-identical whether or not it is batched alongside a longer row (the padding-mask acceptance criterion -- proves the mask actually excludes padded slots from attention/pooling rather than merely zeroing them after the fact), determinism across repeated calls and in `.train()` mode, plus the same wrap/reject/shape edge-case coverage `IndexSetArgumentEncoder`'s own tests already had (out-of-range wraparound, empty batch, empty index subset, non-positive `max_positions`/`arg_dim`). `tests/test_argument_encoder_audit.py` is updated in the two places that exercised the *production default* rather than `IndexSetArgumentEncoder` directly: `audit_phase_a1_default_argument_encoders` now finds no SELECT collision (renamed from `test_phase_a1_audit_select_collides_in_every_checked_seed` to `test_phase_a1_audit_select_no_longer_collides_after_d003`, docstring explaining the change is the intended consequence of D-003 landing, not a regression), and a new test confirms `require_order_preserving_select_encoder` (ADR-0031's STOP GATE guard) no longer raises for `default_argument_encoder("SELECT")`. All tests that construct `IndexSetArgumentEncoder` directly are untouched and still pass, since that class's own behavior did not change.

## ADR-0035 — A1-R005D-006 STOP GATE fails: FiLM/gated-multiplicative conditioning narrows COUNT's causal gap but still falls far short; basis modulation is actively worse than additive

**Status:** Accepted

**Decision:** Task A1-R005D-006 (`docs/CODEX_TASKS_A1_R005_RETRY.md`, "Conditioning architecture comparison," STOP GATE) is recorded as **no variant passed**. `apc.primitives.conditioning` gained a common abstract base `ArgumentConditionedPrimitive(Primitive, ABC)` (`forward_from_calls` shared, `forward(h, *, argument_values, gate=1.0)` abstract) and two new subclasses implementing the two alternative formulas the task text names:

- `FiLMConditionedPrimitive` (**V1**, gated multiplicative): `gamma, beta = split(FiLM_i(e_a))`; `delta = B_i(phi((1 + gamma) * u + beta))` -- the argument multiplicatively gates the content projection `u = A_i(h)` itself, rather than only ever being summed alongside it.
- `BasisModulatedConditionedPrimitive` (**V2**, basis modulation, the task's own "optional" variant, implemented here since it is cheap at this experiment's scale): `mix = softmax(mix_proj(e_a))`; `c = mix @ basis` (`basis`: a shared `[num_basis, rank]` learned dictionary, `num_basis=8`); `delta = B_i(phi(u + c))` -- keeps V0's additive-sum structure but constrains the argument's reachable conditioning vector to a small convex combination of shared basis directions instead of a free linear map.

`ConditionedPrimitive` (**V0**, unchanged) is the third variant. `apc.core.execution._route_and_apply_oracle_calls`'s dispatch check was generalized from `isinstance(primitive, ConditionedPrimitive)` to `isinstance(primitive, ArgumentConditionedPrimitive)` (a strict widening -- every existing call site's behavior is unchanged) so V1/V2 route through `forward_from_calls` the same way V0 already did, with no other change to that module. `apc.evaluation.count_counterfactual_gate` (ADR-0033/ADR-0034's already-validated gate) gained a `variant`/`num_basis` parameter threaded through `_build_primitive_bank`/`_train_primitives`/`run_count_counterfactual_gate[_multi_seed]`, defaulting to `ConditioningVariant.ADDITIVE` (byte-identical to every pre-D-006 call); new module `apc.evaluation.count_conditioning_architecture_gate` (`scripts/count_conditioning_architecture_gate.py`, `configs/phase_a1_count_conditioning_architecture_gate.yaml`) runs all three variants **unconditionally** (no early stopping, unlike D-005's staged sweep) against A1-R005D-004's own baseline config, unmodified ("Keep Stable Core and data fixed" -- `primitive_rank=8`, `primitive_train.steps=10000`, `arg_dim=16`, identical to ADR-0033/ADR-0034), then applies the task's own selection rule: disqualify a non-baseline variant if its mean Correct *and* mean effectful-Wrong-argument both exceed V0's own ("do not choose a model that raises Correct and Wrong together"), then choose the highest-causal-gap variant among the rest that actually passes (`None` if none do).

1. **V1 (FiLM) is a real, measurable improvement over V0, but far short of passing.** Causal gap rises from `0.114` to `0.174` (+53% relative) and Correct rises from `0.450` to `0.510`, while effectful-Wrong-argument *drops* from `0.262` to `0.231` -- i.e. FiLM's multiplicative gating genuinely makes the residual somewhat more argument-selective, not merely more globally accurate (the "do not choose a model that raises Correct and Wrong together" guard explicitly did not trigger for this reason). This is consistent with F3's diagnosis (`docs/design-docs/PARAMETERIZED_PRIMITIVE_RETRY.md`: summing content and argument signals before the shared nonlinearity lets the network under-weight the argument term) and with FiLM being the more direct fix for exactly that failure mode. But `0.174` is barely a third of the `0.50` causal-gap requirement, and Correct (`0.510`) sits far below `0.90` -- comparable in magnitude to A1-R005D-005's best capacity-only stage (`steps_x4`, gap `0.222`, ADR-0034), not a qualitative breakthrough. Changing *how* the argument enters the residual helps about as much as quadrupling the training budget did; neither is sufficient alone.
2. **V2 (basis modulation) is actively worse than V0 on every arm that matters.** Correct falls to `0.368` (below V0's `0.450`), effectful-Wrong-argument *rises* to `0.318` (above its own `0.30` ceiling -- the only variant here to fail that specific criterion, `effectful_wrong_argument_passed=false`), and the causal gap collapses to `0.032`, barely above zero. Constraining the argument's reachable conditioning vector to a small (`num_basis=8`) shared dictionary evidently removes representational capacity `COUNT` needs -- unlike V1, this result does *not* support "the argument's effect should be structurally constrained" as a fix; if anything it is evidence against F3's alternative reading ("an unconstrained conditioning map is too easy for training to route around"). The dictionary is shared and mixed by a *learned* softmax rather than reading the argument value more directly, so part of this drop may also reflect a harder optimization landscape (an extra softmax indirection) rather than a capacity ceiling per se; this run does not distinguish the two, and no further architecture change is made here to do so (out of this task's scope).
3. **`None` is identical (`0.336`) across all three variants**, for the same reason ADR-0034 already established: `None` depends only on the frozen, seed-identical Stable Core (`apc.core.execution.evaluate_exact_match_no_primitive`), which no conditioning-formula change touches.

Taken together, this rules out "the argument-conditioning formula is simply broken" as a full explanation (V0/V1/V2 all reach non-trivial, argument-effect-rate-1.0-backed Correct scores in the 0.37-0.51 range, and family selectivity remains intact throughout, `family_count_passed=true`), while also showing formula choice is not a free lever either -- one structural change (FiLM) helps meaningfully, a superficially related one (basis modulation) actively hurts, and neither reaches the required bar. The most direct reading is that F3 (weak additive conditioning) was a real but partial contributor -- V1's improvement corroborates it -- but not the dominant bottleneck on its own, since even removing the additive-sum structure entirely still leaves COUNT's Correct at barely half the `0.90` target.

**Consequence:** Per `AGENTS.md`'s STOP GATE discipline, A1-R006 remains blocked (unchanged since ADR-0029); per `docs/CODEX_TASKS_A1_R005_RETRY.md` A1-R005D-006's own "STOP if controlled COUNT still cannot pass," this is exactly that outcome. No further architecture or capacity change is made in this task in response to the result (`AGENTS.md`'s "do not hide negative results by ... increasing model size prematurely"). `docs/CODEX_TASKS_A1_R005_RETRY.md`'s own queue continues to A1-R005D-007 (BIND counterfactual gate) and A1-R005D-008 (SHIFT/SELECT sequence gates) -- both still gated on this STOP GATE's failure per the file's own header ("A1-R006 remains blocked until A1-R005D-009 passes"), and neither is implemented here, per `AGENTS.md`'s "Completion of one task does not authorize beginning the next task." A candidate follow-up this task surfaces but does not pursue: FiLM's partial gain and basis modulation's regression together suggest the next diagnostic step, if this retry sequence returns to COUNT specifically rather than proceeding to BIND/SHIFT/SELECT, is combining V1's gating with A1-R005D-005's own best capacity finding (`rank_16`, gap `0.203` at no extra training cost) rather than either lever alone -- not attempted here, since this task's own scope is the conditioning-formula comparison in isolation at the fixed baseline capacity, matching every earlier retry task's one-variable-at-a-time discipline. ## ADR-0036 — A1-R005D-007 STOP GATE fails: BIND's causal gap is statistically zero -- Correct, effectful Wrong argument, and None are indistinguishable, and all three match a content-only "last pair" heuristic

**Status:** Accepted

**Decision:** Task A1-R005D-007 (`docs/CODEX_TASKS_A1_R005_RETRY.md`, "BIND counterfactual gate") is recorded as **FAIL**. New module `apc.evaluation.bind_counterfactual_gate` (`scripts/bind_counterfactual_gate.py`, `configs/phase_a1_bind_counterfactual_gate.yaml`) runs A1-R005D-004's own counterfactual-group protocol (ADR-0033) against `BIND` instead of `COUNT`, at the identical baseline architecture (V0/additive `apc.primitives.conditioning.ConditionedPrimitive`, `primitive_rank=8`, `arg_dim=16`, `core_train`/`primitive_train` byte-identical to `configs/phase_a1_count_counterfactual_gate.yaml`) -- per this task's own text, there is no reason to re-run A1-R005D-006's conditioning-architecture comparison for `BIND` specifically, so this task does not repeat it.

`BIND` (`apc.environments.operations.BindOp`) differs from `COUNT` in the two ways that required a new (not reused) group generator: (1) it needs an *even*-length key/value input (`is_valid_for_length`), so `_valid_bind_lengths` restricts candidate content lengths to the even values in `sequence_length_range`; (2) its argument (`query_key`) is drawn only from keys *actually present* in the content (`BindOp.sample_params`), not the whole vocabulary, so `generate_bind_counterfactual_groups` searches the content's own distinct present keys (shuffled) for up to `group_size` (default 3) whose looked-up values are pairwise distinct, rather than searching the full vocabulary the way `generate_count_counterfactual_groups` does. Everything else -- frozen task-blind Stable Core pretraining on `BIND`-only i.i.d. examples, oracle-forced primitive training on the counterfactual groups, the three-arm evaluation (Correct / effectful Wrong argument / None, no "Wrong family" arm since exactly one family is registered) plus derived causal gap, and multi-seed aggregation against A1-R005D-004's own thresholds (Correct >= 0.90, effectful Wrong argument <= 0.30, causal gap >= 0.50, `None` <= 0.30 filled in from A1-R005D-004's own precedent) -- mirrors `count_counterfactual_gate` structurally, including its "one persistent family" acceptance criterion (`family_count_passed`, `bank_size == 1` every seed) that A1-R005D-007's own fourth criterion, "one persistent BIND family across keys," restates.

`runs/phase_a1_bind_counterfactual_gate/report.json`/`summary.json` (5 seeds `0-4`, RTX 5060 Ti via WSL2, git commit `7ae9ec8` -- this run predates its own commit, matching every earlier ADR's precedent):

| Arm | Mean | Required |
|---|---|---|
| Correct | 0.332 (stdev 0.004, min 0.328, max 0.339) | >= 0.90 |
| effectful Wrong argument | 0.338 | <= 0.30 |
| None | 0.335 | <= 0.30 |
| Causal gap (Correct - max(effectful Wrong argument, None)) | **-0.005** | >= 0.50 |
| argument_effect_rate | 1.000 (every seed) | (diagnostic, not gated) |

`correct_passed=false`, `effectful_wrong_argument_passed=false`, `none_passed=false`, `causal_gap_passed=false`; `family_count_passed=true` (`bank_size == 1` every seed). Overall **`passed=false`**. `primitive_param_count=3360` (identical to `COUNT`'s V0 primitive -- same `vocab_size`-sized integer-bucket argument encoder, `apc.primitives.conditioning.default_argument_encoder`). Per-seed wall-clock ~346s. `num_unseen_eval_examples=3851` from `1400` groups (mean realized group size `2.75`, below `COUNT`'s own -- expected, since `BIND`'s per-group candidate pool is the content's own handful of distinct present keys rather than the whole vocabulary; `min_unseen_eval_examples=2500` was set with this margin in mind and cleared it, `argument_effect_rate=1.0` confirming every realized pairing is effectful by construction as designed).

**Reason:** This is a qualitatively different failure from `COUNT`'s (ADR-0033/0034/0035): for `COUNT`, Correct was always measurably *above* the Wrong-argument/None controls (e.g. `0.450` vs. `0.262`/`0.336` at baseline) -- a real but insufficient causal signal. For `BIND`, Correct (`0.332`), effectful Wrong argument (`0.338`), and None (`0.335`) are statistically indistinguishable (causal gap `-0.005`, i.e. forcing the *correct* key through the trained primitive does no better than forcing a *wrong* key, which in turn does no better than applying no primitive at all). This is not merely "the argument-conditioning signal is weak" (`COUNT`'s F3 diagnosis) -- it is "the measured Correct rate carries no detectable primitive-argument effect whatsoever."

A cheap, offline check (run directly against the same eval-group construction and config, no training/GPU needed -- `generate_bind_counterfactual_groups(0, 1400, ..., vocab_size=10, sequence_length_range=(6, 10), group_size=3)`) confirms what is producing this ~0.33 plateau: predicting, for every example, the *value of the last key/value pair in the content* -- i.e. `content[-1]`, ignoring `query_key` entirely -- gets `0.338` accuracy on the exact same 3851-example unseen distribution this run evaluated on, matching all three observed arms almost exactly. This heuristic's accuracy is explained by the counterfactual-group construction itself: a group's `query_keys` are a uniformly shuffled sample of the content's distinct present keys, so a content-only prediction that happens to equal the value of *one particular* key (whichever key sits last in the sequence) is correct on exactly that fraction of a group's realized members, in expectation `1 / (mean realized group size) ~= 1 / 2.75 ~= 0.36` -- the same order of magnitude actually measured. The frozen Stable Core was pretrained task-blind on `BIND` examples where the query key is never visible in the input at all (`apc.environments.operations.PARAMETERIZED_OPERATION_NAMES`'s hidden-argument design, ADR-0017) and therefore cannot single-token-predict a target that depends on an argument it never sees; "always predict the last pair's value" is a natural, easily-learned, argument-independent fallback for exactly this non-identifiable pretraining objective (attending to the most recent position requires no real key-based content search). That the *trained* `BIND` primitive's Correct/Wrong-argument arms land on the same plateau as the argument-blind `None` arm indicates the primitive is not measurably shifting behavior away from this baseline in either direction, in contrast to `COUNT` where the primitive at least moved Correct above `None`.

This points to a `BIND`-specific bottleneck distinct from `COUNT`'s F3/F4: `BIND` is a genuine content-addressed associative lookup -- the model must locate *which position* in the sequence holds the queried key and read the value one slot to its right, a search-and-select operation over an argument-dependent position, not a fixed transformation of a scalar summary (`COUNT`'s tally) or a rotation (`SHIFT`). A rank-8 additive residual bolted onto a frozen backbone (`delta = B(phi(A(h) + C(e_a)))`) conditions the *whole* residual on the argument uniformly across sequence positions; it has no structural mechanism to make the query argument steer *attention over content positions* specifically, which is plausibly what locating a matching key requires. This is a new candidate explanation, not previously named in `docs/design-docs/PARAMETERIZED_PRIMITIVE_RETRY.md`'s F1-F4 (all stated in terms of `COUNT`'s scalar-output structure); it is recorded here rather than acted on, per STOP GATE discipline.

**Consequence:** Per `AGENTS.md`'s STOP GATE discipline, A1-R006 remains blocked (unchanged since ADR-0029). No architecture change is made in response to this result -- this task's own scope is running the established counterfactual protocol at the established baseline architecture, not diagnosing or fixing `BIND` specifically (`AGENTS.md`'s "do not hide negative results by ... increasing model size prematurely" applies equally to reactively redesigning the primitive mid-task). `docs/CODEX_TASKS_A1_R005_RETRY.md`'s queue continues to A1-R005D-008 (SHIFT/SELECT sequence gates), not implemented here, per `AGENTS.md`'s "Completion of one task does not authorize beginning the next task." The candidate `BIND`-specific bottleneck this task surfaces (content-addressed lookup needs argument-steered attention over positions, not a uniform additive residual) is left as a candidate for whoever next revisits `BIND`'s own architecture -- out of this task's scope to pursue. Run artifacts preserved at `runs/phase_a1_bind_counterfactual_gate/` (`config.yaml`, `report.json`, `summary.json`, `system.json`, one `seed_<n>/{report.json, core_metrics.jsonl, primitive_metrics.jsonl}` per seed). New tests: `tests/test_bind_counterfactual_gate.py` (48 cases: `_valid_bind_lengths`, group construction/distinctness/determinism/present-key-only sampling, config validation including the even-length check, bank construction, report shape, multi-seed aggregation, threshold constants -- mirroring `tests/test_count_counterfactual_gate.py`'s convention, minus the A1-R005D-005/006-specific gradient-norm/conditioning-variant cases which are out of this task's scope). Full suite (`python -m pytest -q`: 1033 passed, 1 skipped, up from 985/1 before this change), `python -m ruff check .`, and `python -m mypy src/apc` (57 source files) are all clean after this change.

## ADR-0037 — A1-R005D-008 STOP GATE fails for both SHIFT and SELECT: multi-token exact match collapses under length compounding; causal gaps are small but nonzero; the cross-attention fallback is not built because its own precondition does not hold

**Status:** Accepted

**Decision:** Task A1-R005D-008 (`docs/CODEX_TASKS_A1_R005_RETRY.md`, "SHIFT and SELECT sequence gates") is recorded as **FAIL for both operations**. New module `apc.evaluation.sequence_counterfactual_gate` (`scripts/sequence_counterfactual_gate.py`, `configs/phase_a1_shift_counterfactual_gate.yaml`/`phase_a1_select_counterfactual_gate.yaml`) reuses A1-R005D-004/A1-R005D-007's own counterfactual-group protocol (ADR-0033/ADR-0036), generalized to a *multi-token* output and parameterized by `operation` (`SHIFT` or `SELECT`) since this one task names both -- unlike `count_counterfactual_gate`/`bind_counterfactual_gate`, each built for a single, separately-requested task.

`SHIFT`'s candidate argument values (`amount`) are `range(length)`, searched the same way `COUNT`'s target search works; `SELECT`'s (`indices`) are every `output_length(length)`-sized subset of `range(length)`, fully enumerated via `itertools.combinations` (at most `math.comb(10, 5) = 252` at this config's lengths, cheap to enumerate exactly rather than search). Both operations register exactly one V0/additive `apc.primitives.conditioning.ConditionedPrimitive` -- "the selected low-rank conditioned architecture" (this task's own phrase) resolves to that same baseline, since neither A1-R005D-005 (ADR-0034, "no stage passed") nor A1-R005D-006 (ADR-0035, "no variant passed") actually selected anything better; nothing else has ever been promoted over it in this retry sequence. `SELECT`'s own "order-preserving argument encoder mandatory" requirement needed no new code: `build_conditioned_primitive("SELECT", ...)` already returns `OrderPreservingIndexSetArgumentEncoder` by default (Task A1-R005D-003/ADR-0032), confirmed directly by `test_build_primitive_bank_select_uses_order_preserving_encoder`. This task adds two new metrics beyond `COUNT`/`BIND`'s three-arm shape, both computed from the raw greedy-decoded predictions `apc.core.execution.evaluate_exact_match_with_oracle_calls`/`evaluate_exact_match_no_primitive` already return: **token accuracy** (`_token_accuracy`, per-position match rate, denominator always `len(target)`) and **length-stratified metrics** (`_length_stratified_metrics`, Correct-arm exact match/token accuracy bucketed by `len(input_tokens)`, diagnostic only, not gated).

`runs/phase_a1_shift_counterfactual_gate/`, `runs/phase_a1_select_counterfactual_gate/` (5 seeds `0-4` each, RTX 5060 Ti via WSL2, git commit `7ae9ec8` -- both runs predate this ADR's own commit, matching every earlier ADR's precedent):

The dominant explanation for the overall failure is not "no argument signal" but "multi-token exact match is a much harder bar than this architecture's absolute performance can clear at all," exactly the concern ADR-0029 flagged as "multi-token exact-match compounding": Correct's own *token* accuracy (`0.258`/`0.487`) is itself far below the `0.95` target, so even a perfect argument-conditioning signal riding on top of this base rate could not lift *sequence*-level exact match anywhere near `0.85` -- getting every one of `6-10` positions right simultaneously requires the per-position accuracy far closer to `1.0` than either operation reaches. The length-stratified table confirms this compounding directly and quantitatively: `SHIFT` exact match roughly halves from length `6` (`0.223`) to length `10` (`0.120`); `SELECT`'s falls by nearly `7x` (`0.189` to `0.032`) over the same range, consistent with `SELECT`'s output tokens each depending on a *combinatorial* argument (an index subset) rather than `SHIFT`'s single scalar rotation, compounding argument-sensitivity error on top of position-count error. `SELECT`'s much higher token accuracy despite its much lower exact match (`0.487` vs. `SHIFT`'s `0.258`, while `SELECT`'s output is only `output_length(length) = max(1, length // 2)` tokens long, roughly half `SHIFT`'s full-length output) is consistent with this: fewer positions to get right raises the per-token rate even as the compounding exact-match penalty (more positions relative to the *argument's own combinatorial space*) drags exact match down faster.

**On the cross-attention fallback:** A1-R005D-008's own text conditions building "a minimal tiny cross-attention primitive as an explicit alternative class" on the gate failing "*despite strong COUNT/BIND results*." That precondition is false: `COUNT` failed its own STOP GATE at every architecture tried (V0/V1/V2, ADR-0033/0034/0035, best causal gap `0.174`, Correct `0.510`), and `BIND` failed even more severely, with a causal gap statistically indistinguishable from zero (ADR-0036). A `SHIFT`/`SELECT` failure at the same baseline architecture is exactly what that pattern would predict, not a surprising, isolated signal that would license inferring "`SHIFT`/`SELECT` specifically need a different primitive class" -- the task's own conditional is designed to isolate that inference to a case where the *other* three operations already demonstrate the architecture is sufficient and only sequence-output operations are the outlier. Building a new primitive class here regardless would be exactly the "hide a negative result by escalating architecture" pattern `AGENTS.md`'s STOP GATE discipline prohibits, since the actual evidence pattern across all four operations tested so far (`COUNT`, `BIND`, `SHIFT`, `SELECT`) is convergent, not isolated: none clear this retry sequence's baseline-architecture bar, at any of the architectural variations tried for `COUNT` specifically. This module therefore implements only the counterfactual gate itself; no cross-attention primitive class exists in this codebase after this task.

**Consequence:** Per `AGENTS.md`'s STOP GATE discipline, A1-R006 remains blocked (unchanged since ADR-0029).
