## 4. T48：閉ループ比較と設計変更

### 4.1 v3に対するゲート（`runs/t48-cv-*`、`runs/t48-veto-20260926-a`）

- ゲートは、ルーターがCandidateを提案したときだけ参照される。そのため、Candidate起動22セルと、起動しない条件2つずつ（一致確認用）だけを再実行した。確認用の条件はすべてv3と一致した。
- 交差検証：偶数seedで学習したゲートを奇数seedで評価し、逆も行った。ゲートは各7ノード。
- 結果は§0の表のとおり。常時拒否では、初期に対して11条件を失った。
- 分岐点の調査：失った条件の多くで、最初のCandidate起動時点で初期ルーターはBaseを選んでいた。その後、初期ルーターが配置（place）・移送（transit）を選ぶ場面で、再学習ルーターは別の判断をしていた。3314・3359では、Candidateの起動前から分岐していた。

### 4.2 親委譲拡張（`scripts/make_deferring_bank.py`、`runs/t48-deferring-20260926-a`）

- 銀行に役割 `parent_router` を加える。ルーティングの規則：
  - 再学習ルーターの出力が候補クラスなら、Candidateを選ぶ。ゲートがあれば、ゲートが拒否した場合は親の判断に戻す。
  - それ以外は、親ルーターの判断（Base / 回復 / 移送 / 配置）に従う。
- 調整群（`runs/t48-tune-defer-20260926-a`、120,663 step）：68/123。Candidate非起動の106条件は、step数まで初期と一致した。
- 反実仮想（`runs/t48-cf-defer-20260926-a`、156分岐、181,578 step）：
  - 78点すべてで継続分岐が記録と一致した。
  - 「適用」ラベルは11点。ゲートは全点学習で7ノード、交差検証の各ゲートは3ノードと7ノード。
- 交差検証ゲート（`runs/t48-cv-defer-*`）：68/123（得3103 / 失3076・3077・3121・3124）。
