## 1. 目的と課題

これまでの実験において、運搬局所 Candidate（`transit_candidate.pt`）は高い性能を示していたが、その介入条件（ルーター／ゲート）は以下のような**手設計コード（ハードコードされた if 条件）**に依存していた：
```python
if raw_id == 4 and cube[2] > cube_init_z + 0.08 and cube[2] > goal[2] + 0.02:
```
この手設計条件は、APC 理論が目指す「状態や行動から自律的に介入タイミングを判断する」という原則（命題 H2: 適用可能性）に対して未解決の課題であった。

本実験（W4 / T11）では、固定された行動モデル（Base CART + Transit CART + Place CART）をそのまま用い、手設計ゲートを状態・目標・Base提案行動から介入の是非を判別する**小型学習型ゲート（Learned CART Gate）**へ置き換え、以下の問いを検証した：
1. データから自律的に介入境界・閾値を学習できるか？
2. 学習型ゲートは手設計ゲートと同等の閉ループ安定成功（HoldContinuousSuccess 20 steps）を達成できるか？
3. 過去課題（Place, Pick）に対する誤介入（False Positive）をゼロに抑え、既存能力を完全維持できるか？

---

## 2. 学習型ゲート（Learned CART Gate）の設計と学習結果

### 2.1 入力特徴量とデータセット
- **入力特徴量**:
  - `raw_is_4`: Base CART が上方への引き上げ行動（`primitive 4: hand_z_plus`）を提案したか否か（0 or 1）
  - `grasped`: キューブ把持状態（0 or 1）
  - `cube_lift_z`: 初期机上高に対するキューブの浮上高さ ($z_{\text{cube}} - z_{\text{init}}$)
  - `cube_rel_goal_z`: 目標高さに対するキューブの相対高さ ($z_{\text{cube}} - z_{\text{goal}}$)
  - `goal_z`: 目標の絶対高さ（Pick等の空中目標とPlace等の机上目標を識別）
  - `dist_xy_to_goal`, `dist_z_to_goal`: 目標までの水平・垂直距離
  - `cube_z`: キューブの絶対高さ
- **データセット構成**:
  - **訓練セット（Train）**: 12,332 steps（過去の運搬拡張データセット、アブレーション探索run、空中目標を持つPick/Place探索runを含む）。正例（介入必要）: 106 steps。
  - **検証セット（Val / Retention）**: 2,396 steps（独立保留評価シード: seed 3011, 3001, 3201）。正例: 1 step。

### 2.2 学習された決定木ルール（CART）
モデル形式: `primitive_tree.py` の `CART` クラス（PyTorchバッファ、勾配パラメータ0）。
- **ノード数**: 5 ノード
- **ファイルサイズ**: 3,335 bytes (3.3 KB)
- **格納値数**: 10
- **獲得されたルール**:
```text
if raw_is_4 <= 0.5000:
  -> 介入しない (Class 0, Delegate to Base)
else: (raw_is_4 > 0.5000)
  if cube_rel_goal_z <= 0.0802:
    -> 介入しない (Class 0, Delegate to Base)
  else: (cube_rel_goal_z > 0.0802)
    -> 運搬Candidateへ介入 (Class 1, Activate Transit)
```

### 2.3 分類性能（オフライン評価）

データ内の空中目標（Pick課題など）を適切に負例として学習させた結果、相対高さ閾値 `cube_rel_goal_z > 0.0802` が自動的に抽出され、誤介入・見逃しともにゼロ（100% 整合）を達成した。

## 3. 物理シミュレーション閉ループ対照実験

同一の物理環境・固定行動モデル（`base_selector.pt`, `place_candidate.pt`, `transit_candidate.pt`）を用い、手設計ゲートと学習型ゲートの閉ループ挙動を比較した。

| 課題名 | シード | 課題の位置付け | 手設計ゲート（旧） 終了Step | 学習型ゲート（新） 終了Step | ステップ差 | 連続維持 Step数 | 安定達成判定 | 実行Runディレクトリ |
|---|---|---|---|---|---|---|---|---|
| `APC-FetchTruePlaceFar-v1` | **3011** | 新規・複合課題（運搬拡張+配置） | 819 | **819** | **±0** | **20 / 20** | **完全達成（完全同一再現）** | `runs/apc-t11-gate-eval-seed3011-20260925-a` |
| `APC-FetchPlaceCubeFar-v1` | **3001** | 過去課題（配置） | 833 | **833** | **±0** | **20 / 20** | **完全達成（副作用ゼロ）** | `runs/apc-t11-retention-place-seed3001-20260925-a` |
| `APC-FetchPickCubeFar-v1` | **3201** | 過去課題（把持・持ち上げ） | 744 | **744** | **±0** | **20 / 20** | **完全達成（副作用ゼロ）** | `runs/apc-t11-retention-pick-seed3201-20260925-a` |

### 3.1 閉ループ挙動の分析
1. **新規複合課題（seed 3011, True Place）**:
   - Step 762 において、Base CART が提案した `raw_id == 4` に対して、学習型ゲートが即座に Class 1 を判定。
   - 運搬 Candidate（`transit_candidate.pt`）へ介入を委ね、-Y 方向への水平補正（`primitive 3`）を実行。
   - その後、Step 800 で配置ゾーンに到達して配置 Candidate へスムーズに引き継がれ、Step 819 で連続 20 steps 達成により完全終了。手設計ゲートと全く同一の軌跡を再現した。
2. **過去課題（seed 3001, Place & seed 3201, Pick）**:
   - 空中への持ち上げ動作中、`cube_rel_goal_z <= 0.0802` が維持されているため、学習型ゲートは一度も誤介入せず（誤介入数 0）、Base CART の正常な持ち上げ・運搬を邪魔しなかった。
   - 過去タスクの成功率・ステップ数・連続維持性能に一切の劣化を生じさせないことが実証された。

## 4. 結論と理論的進展

1. **命題 H2（適用可能性）の強力な支持**:
   - 手設計のルールベース分岐コードを完全に排除し、観測と Base 提案行動から学習されたわずか 5 ノード（3.3 KB）の CART ゲートによって、最適な介入タイミングの自律選択が可能であることを証明した。
2. **手設計対比での非劣性（完全同一性能）**:
   - 新規課題（seed 3011: 819 steps）、過去配置（seed 3001: 833 steps）、過去把持（seed 3201: 744 steps）の全条件において、手設計ゲートと 1 ステップの狂いもなく完全同一の物理挙動を再現した。
3. **極小サイズとパラメータゼロの継承**:
   - ゲートモデル自体も深さ 2、ノード数 5 の極小決定木であり、勾配パラメータ 0、総保存量 3.3 KB という APC の定着・配布原則（H3, H4）に完全に合致している。
