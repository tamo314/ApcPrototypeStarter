## 2. タスク

### T45 監査
- T42を3114を除いた39条件で再集計し、結論が変わるかを記録する。

### T46 誤介入の記述分析（`scripts/analyze_t46_interventions.py`）
- Candidate起動セルを初期銀行との比較で gain / loss / both_fail / both_success に分類し、起動時点の状態を記録する。
- 確信度・停滞長のしきい値で開ループの除外数を数える（閉ループ効果ではない）。

### T47 反実仮想ラベルによる適用可能性ゲート
1. 課題列自動版 v3 銀行（前段の `stream_v3`）を、調整群（約123条件）で実行する。
2. 各Candidate決定点 k（コミット中を除く）で、prefix replayから2分岐を実行する。
   - 継続：そのまま続行
   - 拒否：k以降Candidateを使わない（ルーターが候補を選んだらBaseに戻す）
3. ラベル：継続が拒否より良い（成功、または双方失敗で最終距離が 0.01 m 以上近い）なら「適用」、それ以外は「不適用」。
   - 継続分岐の結果が実際の結果と一致するか（再現性）も記録する。
4. ゲート：router_v2特徴（16次元）上の浅いCART（深さ≤3、葉≥3）。
   - 銀行の役割 `gate` として保存し、ルーターが候補を選んだときだけ参照する（拒否すればBase）。
   - Candidate・ルーター本体は変えない。

### T48 調整群での閉ループ検証（交差検証）
- 調整群をseedの偶奇で2分割する。片方で学習したゲートを、もう片方で評価する。
- 比較する銀行：
  - v3（ゲートなし）
  - v3＋ゲート（交差検証版）
  - v3でCandidateを常に拒否（ルーター再学習だけの効果を分離するため）
  - 初期銀行
- 最終版のゲートは調整群全体で学習する。ここでの結果は選択に使うだけで、合否の基準にはしない。

### T49 最終独立確認（3130〜3189、60条件、1回のみ）
- 評価する銀行：初期、v3、v3＋ゲート（全調整群で学習）、v3＋常時拒否。
- 報告項目：Wilson 95%区間、初期銀行に対して得た条件と失った条件、Candidate起動数とそのうちの成功数。

### T50 文書化

## 3. 事前に決める判断規則

- ゲート版がT49で初期銀行・v3を上回らなければ、「現特徴での適用可能性の学習は独立汎化しない」と記録する。区間が重なる場合は「差を検出できない」と書く。
- 反実仮想の再現性が低い（継続分岐と実際の結果の不一致が1割を超える）場合は、ラベルを使わずに原因を記録する。
