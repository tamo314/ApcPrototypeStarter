## 1. T32-R1：実遷移・共通特徴・成功判定・来歴

### 1.1 実装

- `src/apc_maniskill/experience_loop.py`
  - `run_episode`：`policy.action()→env.step()→policy.after_step()` の直後に1レコードを書く。終端stepも含む。
  - レコード項目：
    - 識別・来歴：`run_id, episode_id, environment_seed, control_step, event_id, source_event_hash, active_bank_hash`
    - 状態：`s_t`, `s_tp1`
    - 選択：`base_proposed_id, router_class, selected_module, proposed_id, executed_id, submitted_action, override_reason_code`
    - 実行結果：IK 3フラグ（台車modeでは `null`）、ターゲット更新有無、実測変位（手先・物体・台車xy/yaw・目標距離の進捗）、報酬成分、`terminated`/`truncated`、経過step・秒
  - `router_features`：旧ルーターと同じ算術の12特徴。学習・実行で同じ関数を使う。
  - `candidate_features`：schema v5（`LearnedSelector` と同一）。
  - レコードに実行時の入力ベクトル `router_x`、`router_x2`、`candidate_x` を保存し、学習時に再構成しない。T32の固定値代入（手先距離0.01・gripper推測）は廃止した。
  - `RoutedSelector`：旧 `UnifiedRouterSelector` と同じ規則。診断用の強制（`force`）・スクリプト・配置ゲートのフックと、各stepの決定記録を持つ。
- `scripts/run_t32r1_transitions.py`：オンライン検出器（`AutonomousDeficitDetector`）を実行ループ内で更新する。イベントは銀行hash・観測履歴パスを含むJSON（`apc_deficit_event_v2`）で保存する。

## 3. T32-R3：イベント起動の局所option探索と学習

### 3.1 方式（`src/apc_maniskill/acquisition.py`、`scripts/run_t32r3_acquire.py`）

- 入力は検出イベントJSONのみ。イベントがなければ学習しない（`no_event_no_learning`）。
- 同一 `event_hash` は重複としてスキップする。親銀行hashと不一致なら `stale_bank_skipped`。種類が既知なら `recurrence_of_known_kind` と記録する。
- 探索開始：検出直後のstep（v4以降。v1〜v3は停滞開始点）。
- 選択肢（全比較方式で共有する人の事前情報）：既存ID＋実行器の整定保持（手先・回転8 step、台車25 step）。
  - 単発：ID 0〜5, 13, 16〜19
  - 3回反復：ID 0〜5
  - 直前の選択の逆操作は候補から外す。
- 各決定点で、全選択肢と「現行銀行のまま」を比較する。評価は、選択肢の実行後に**現行銀行を250 step動かした終端の結果**で行う。
  - 評価値 = −終端距離 − 0.0005×拒否数 − 0.2×（把持後の喪失）+ 0.2×成功
  - 銀行のままが最良（差3 mm未満）になった時点で引き継ぐ。
- 学習：
  - Candidate：決定時点のschema v5状態 → 選ばれた選択肢のCART（`OptionSelector`。保持は選択肢の一部）
  - Router：親ルーターの自己ラベル（リプレイ軌跡）＋決定状態のCandidateラベル（重み50）＋引き継ぎ後の親ルーターの判断

### 3.2 失敗を含む変遷

| run | 変更点 | 結果 |
|---|---|---|
| `…-a-failed-oscillation` | 評価＝区間内最小距離 | 左右旋回（18/19）が交互に選ばれ無進捗（112,140 step消費） |
| `…-b` | 終端距離評価・逆操作禁止 | 3014は旋回2回で停止し未成功。Candidate学習行の55/58がCONTINUE |
| `…-c` | option Candidate、3回反復選択肢 | 3014・3020とも獲得軌道が成功。置換設計 |
| `…-d` | 拡張設計（5クラス）・ルーターv2・イベント時点開始 | 3014：`(1,3)→(13,1)→(1,3)` で977 step成功。3020：`(0,3)` で783 step成功 |
| `…-e` | dの探索結果を再利用し、Pick/Place開発リプレイを加えてルーターだけ再学習 | ルーター43ノード |

- 探索費用：c 73,881 step、d 100,478 step（replay各約1.6k）。学習は数秒。
- Candidate_A：5ノード・4行・4,869 bytes。決定行が極めて少ない。
- ルーターv2の追加特徴（学習と実行で同一関数、オンライン/オフラインの差 ≤2.3e-7）：
  - 停滞step数（検出器と同じ規則による観測履歴）
  - ロボット座標系での目標−物体の方向（x・y）
  - 直前stepのIK拒否
- option commitment：開始した選択肢は保持を終えるまで継続する。把持喪失時は回復層が優先する。
