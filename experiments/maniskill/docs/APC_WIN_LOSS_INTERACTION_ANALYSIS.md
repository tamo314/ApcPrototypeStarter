# APC 勝敗要因の交互作用分析と失敗条件の検討（W8: T24）

作成日：2026-09-25（JST） / 改訂日：2026-09-25（JST）  
対象タスク：W8 / T24（APC アーキテクチャの勝敗要因の整理、失敗条件の分析、および課題の特定）  
対象命題：H2（適用可能性）、H6（合成転移）、H8（資源利得）

---

## 1. 目的と位置付け

本稿（W8 / T24）の目的は、APC（Adaptive Primitive Consolidation）を無条件に肯定することなく、**どのような要因によって利点が生じ、どのような条件下で破綻・劣勢となるか（勝つ条件と負ける条件の交互作用）** を整理し、これまでの実験で確認された失敗事例の物理的メカニズムを客観的に検討することである。

> [!NOTE] 境界確定に関する科学的注意
> 本分析は既存の実験観察と理論的考察に基づく要因整理であり、他条件を固定して目標位置やノイズを連続掃引した系統的な境界実験や、同条件での競合方式（共有モデル＋リプレイ等）との網羅的対照実験ではない。
> したがって、「幾何的境界値や競合に対する勝敗が確定した」と結論するのではなく、**「現行システムにおいて明確な失敗条件と同定された物理的メカニズム」** として扱う。

## 2. 4大要因による勝敗交互作用マトリクス

| 要因 | APC が有利になり得る条件 (Potential Win Condition) | APC が同等・劣勢になり得る条件 (Potential Loss Condition) | 現行実験での観察状況 |
|---|---|---|---|
| **空間・行動局所性** | タスクの変化が特定の時空間区間（運搬・配置）に限定され、Base の大部分を再利用可能 | 状態表現全体や関節角空間全域の大規模変更が必要な場合（End-to-End 更新が有利） | 運搬補正（19 steps）や配置下降の局所追加において有効性を確認 |
| **課題再出現頻度** | 一度獲得したスキルが将来のタスク列で繰り返し再出現する | 全タスクが使い捨て（一回限り）で二度と出現しない場合（定着費用が回収不能） | 課題列において同一 Candidate を再利用できたが、定着総費用と再学習費用の厳密な損益分岐実測は未完了 |
| **障害・外乱階層** | 運動学・軌道計画レベルの幾何的不整合（目標偏差、ドリフト） | 低位物理接触の激しい滑落・反転外乱（手設計安全ガードや高周波反射制御が必要） | 激しい把持脱落に対しては学習決定木単独では対応できず、手設計の回復ガード状態機械に依存 |
| **時間的循環性** | タスクが非循環的な順序フェーズ（把持 $\to$ 運搬 $\to$ 配置）で完了する | 把持と配置を同一エピソード内で反復・往復する循環タスク（終端ラッチが破綻） | 配置モジュール開始後に `latched_place`（終端ラッチ）を使用しており、非循環タスクに限定されている |

## 3. 実測で同定された失敗条件とその物理メカニズム

これまでの実験で確認された失敗事例は、単一の原因にまとめることはできず、異なる物理的要因に基づいている。

### 3.1 失敗条件 1：目標外挿に伴う Transit 不発（Seed 3014）
- **観察事実**: Seed 3014（目標 $y = 0.212\mathrm{m}$）において、1,200 steps タイムアウト失敗。モジュール配分は `base: 1200`、Transit / Place の介入は 0 回。
- **メカニズム**:
  - 運搬 Candidate の学習データ分布は $y \le 0.15\mathrm{m}$ に集中しており、ルーターおよびパッチの幾何カバレッジを大きく逸脱していた。
  - ルーターが Transit を一度も発動できず、Base が目標手前で停滞を続け、配置モジュールへの引き継ぎ条件（1.6 cm）に達しなかった。
  - **要因**: 局所モジュールおよびルーターの幾何的有効範囲外への外挿。

### 3.2 失敗条件 2：早すぎる Place 進入と終端ラッチによるスタック（Seed 3013）
- **観察事実**: Seed 3013（目標 $y = 0.187\mathrm{m}$）において、1,200 steps タイムアウト失敗。モジュール配分は `base: 828, place: 371, transit: 1`。
- **メカニズム**:
  - Step 829 において、キューブと目標の水平距離が約 2.36 cm の状態で `Place` モジュールが発動した。
  - 発動と同時に終端配置ラッチ（`latched_place`）が機能し、以後の 371 ステップにわたり Place モジュールに固定された。
  - しかし、目標許容範囲（2 cm以内）に収まる前に進入したため、Place 方策（下降・解放・静止）が目標手前で微動し続け、接地判定を満たせないままタイムアウトした。
  - **要因**: 引き継ぎ境界判定の不整合と、一度入ると復帰できない手設計終端ラッチの制約。

### 3.3 失敗条件 3：低位把持接触の物理限界（Seed 3204）
- **観察事実**: PickCubeFar Seed 3204 において、1,200 steps タイムアウト失敗。モジュール配分は `base: 1200`。
- **メカニズム**:
  - キューブの初期姿勢・接触角度により、Base 方策が接近・把持を試みるも安定した把持状態（`is_grasped`）を確立できずタイムアウトした。
  - **要因**: 上流の基盤身体方策自体の物理把持限界。

## 4. 総括と今後の検証要件

本分析により、APC アーキテクチャを実環境で機能させるための課題が明確化された：
1. **境界値の厳密な掃引実験**:
   - 単に個別の失敗シードを観察するだけでなく、目標距離 $y$ を 0.05 m から 0.25 m まで連続的に掃引し、どの座標でどのモジュールがどのように失敗するかを定量化する必要がある。
2. **終端ラッチの柔軟化と循環性への対応**:
   - `latched_place` のような不可逆ラッチに依存せず、目標偏差が大きい場合は Transit や Base へ安全に復帰できる双方向・閉ループ引き継ぎ機構が必要である。
3. **同条件での競合方式（共有モデル＋リプレイ）との比較**:
   - 同一の計算予算・同等の環境ステップのもとで、単一モデル＋リプレイ方式と APC がどのような課題順・再出現頻度で逆転するかを直接対照実験で検証することが不可欠である。
