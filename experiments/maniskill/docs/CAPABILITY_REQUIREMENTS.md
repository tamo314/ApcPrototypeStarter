# APC 能力要求表と課題分類（T01）

本資料は、APC 理論検証ロードマップ（`docs/APC_THEORY_VALIDATION_ROADMAP.md`）の W0/T01 に基づき、Fetch マニピュレーション課題における能力要求、既存モジュールの境界、および基準方式の役割を定義する。

---

## 1. 能力要求の因子分解（把持・回復・運搬補正・解放・整定）

単なる配置目標座標の変更と、真の新規能力獲得を厳密に区別するため、タスクを以下の5つの能力要件に分解する。

| 能力層 | 要求内容 | 既存 Base CART (20 ID) の能力 | 不足時の挙動・課題シード | 獲得・対応モジュール |
|---|---|---|---|---|
| **L1 把持 (Grasp)** | テーブル上のキューブへ接近し、両指で挟み込んで持ち上げる | 既知の正面・標準摩擦条件では把持可能 | 初期位置が遠い、またはアプローチ角・摩擦変化時に未把持・途中脱落（seed 3008, 3009） | 凍結 Base または W2 把持回復 Temporary |
| **L2 回復 (Recover)** | 把持失敗または運搬途中の脱落を検知し、退避・再接近して再把持する | **非対応**（空振りのまま次工程へ進む） | 未把持のまま机上を徘徊、または脱落後に目標地点へ空グリッパーを移動 | W2 (T05–T07) で獲得する局所回復 Temporary/Candidate |
| **L3 運搬補正 (Transit)** | 物体を把持したまま、目標XY（±X, ±Y, 対角）へ高さを保ちつつ水平移送する | 上昇動作（primitive 4, 18等）へ偏重し、目標手前で停滞 | 目標XYから 4〜12 cm 離れた位置で停滞、または配置閾値（1.6 cm）へ届かない（seed 3011, 3012） | 運搬パッチ（限定介入 MLP / Candidate CART、T02–T04で拡張） |
| **L4 解放 (Release)** | 目標位置（1.6 cm以内）で下降し、グリッパーを開いて物体をテーブル上に手放す | **非対応**（常に把持維持 primitive 8等を出力） | 物体を保持したまま静止せず把持し続ける | 配置パッチ（Candidate CART: 408 values, 17ノード） |
| **L5 整定 (Settle)** | 物体手放し後、物体とロボット双方が静止し、連続20 step 成功を維持する | **非対応** | グリッパー離脱時の微小接触（バウンド）、または腕の惰性運動 | 新プロトコル `HoldContinuousSuccess`（過渡期接触と安定整定の分離） |

## 2. 基準方式（Baselines）の定義と公平な比較条件

ロードマップ第7節に基づき、APCの優位性を検証するための対照方式を設定する。

| 方式ID | 方式名 | 構成・パラメータ | 役割と判定境界 |
|---|---|---|---|
| **B0** | 凍結 Base CART | 単一 CART (20 ID)、固定重み | 新しい能力が本当に必要であるかの確認（能力不足の証明用） |
| **B1** | 手設計教師／幾何ガード | `TransitGuardSelector` (幾何条件による限定補正) | 到達可能性・診断上の上限参照（自律学習方式とは明確に区別） |
| **B2** | 単一目標条件付き CART | 単一 CART、観測+目標入力を共有 | 銀行やモジュール分割なしで解けるかの対照（全体データで学習） |
| **B3** | 単一目標条件付き MLP | 2層小型 MLP (hidden=128)、観測+目標入力を共有 | 表現力と連続適応の対照 |
| **APC-Direct** | 直接 Candidate CART | 局所データで直接 CART を学習 | Temporary（MLP）を経由する真の価値があるかを検証 (T08) |
| **APC-Modular** | APC Temporary MLP → Candidate CART | 凍結 Base + 運搬パッチ + 配置 Candidate | 本方式：局所獲得・蒸留・実解放・非干渉保持を実証 |

## 3. 命題（H1–H8）と検証マトリクス

| 命題 | 内容 | 主要な検証タスク |
|---|---|---|
| **H1 局所獲得** | 既存能力を凍結したまま、不足する判断だけを学習して新要求に対応できる | T02, T04, T06 |
| **H2 適用可能性** | 正解モジュールIDなしに、実行時状態からモジュールを選択・引き継げる | T11, T12, T13 |
| **H3 行動を保つ定着** | Temporaryの機能を、より小さいCandidateへ性能を落とさず移せる | T08, T09 |
| **H4 実解放** | Temporaryを実行依存から除いても能力を保持できる（最小配布物実行） | T10 |
| **H5 自動閉ループ** | 不足検出から獲得・定着・解放を自律反復できる | T14, T15, T16 |
| **H6 合成転移** | 未学習の組合せで学習済み能力を再利用できる | T17, T18, T19 |
| **H7 継続保持** | 複数回の能力追加後も過去能力を維持できる（破滅的忘却の防止） | T20, T21 |
| **H8 資源上の利得** | 再出現・共有により、同等性能で学習・実行資源を削減できる | T21, T22 |
