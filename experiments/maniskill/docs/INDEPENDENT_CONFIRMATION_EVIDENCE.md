## 1. 目的と検証プロトコル

本実験（W8: T25）は、`docs/APC_THEORY_VALIDATION_ROADMAP.md` に従い、開発フェーズ（W1〜W7）において獲得・定着された適応型プリミティブ統合アーキテクチャが、独立した別プロセスにおいて再現可能であるかを検証することを目的とする。

### 1.1 検証プロトコルと来歴に関する客観的注記
1. **凍結最小自律配布物（`dist_autonomous_bundle_v1`）の利用**:
   - 一時学習アーティファクト（Temporary MLP、オプティマイザ、リプレイバッファ、教師データセット）を一切含まない配布ディレクトリのみを参照。
   - 勾配パラメータ数 0、4つのチェックポイントモデルファイルの合計サイズ **39,817 bytes（38.88 KB、合計200ノード）**。
2. **評価条件とルーター学習データセットの重複（来歴の客観的開示）**:
   - 本評価で用いたシード群のうち、**Place 3002、TruePlace 3010、TruePlace 3013 の 3 条件は、`train_unified_router.py` のルーター学習用入力軌跡リストに含まれていた**。
   - したがって、これら 3 条件は「開発過程で一度も参照されていない完全未使用条件」ではなく、**「ルーター学習に既知の軌跡が含まれる条件における再現確認」** として厳密に位置付ける必要がある。真の未学習条件（ルーター学習にも含まれない条件）はその他のシード群である。
3. **厳格な判定条件（`HoldContinuousSuccess` 20 steps）**:
   - 目標許容範囲内およびロボット・物体の完全静止を **20 control steps 連続して維持** することをもって達成と判定。
4. **全失敗を含む透明な報告**:
   - タイムアウト失敗を含む全 11 エピソードの結果を客観的に記録・報告する。

## 4. 物理的挙動と失敗要因の客観的分析

### 4.1 TC 08（Seed 3013: 1,200 steps タイムアウト）のステップログ詳細分析
報告書初期版における「Placeへの引き継ぎが不発」という記述は、ステップログの事実と矛盾していた。実測ログ（`steps.jsonl`）の精査により判明した実態は以下の通りである：
1. **Place モジュールへの進入**:
   - Step 828 まで Base で実行された後、**Step 829 において `patch_applied: True`（Placeモジュール）が実際に発動**した。
   - 発動時点でのキューブと目標の水平距離は `dist_xy = 0.0236m`（約2.4 cm）、高さは `cube_z = 0.0337m` であった。
2. **終端配置ラッチ（`latched_place`）による固定化**:
   - `latched_place` 機構により、一度 Place モジュールが発動すると Base や Transit への逆戻りが禁止される。
   - このため、**Step 829 から終了 Step 1199 までの 371 ステップにわたり Place モジュールが選択され続けた**（モジュール計数 `place: 371`）。
3. **未達タイムアウトのメカニズム**:
   - 水平距離が目標許容範囲に寄り切る前に Place モジュールに入ったため、Place 候補方策（下降・解放・静止）が実行されるも、水平位置が目標範囲（2cm以内）に届かず、かつ接地判定を満たせないまま空中で微動を継続し、ステップ上限（1,200 steps）に達した。
4. **Seed 3014（W6）との本質的相違**:
   - Seed 3014 は目標が $y=0.212\mathrm{m}$ と極端で Transit が発動せず Base のままタイムアウトした（Place 介入 0 回）。
   - 対して Seed 3013 は目標 $y=0.187\mathrm{m}$ において「早すぎる Place 進入と終端ラッチによるスタック」でタイムアウトした（Place 介入 371 回）。
   - したがって、両者を同一の「引き継ぎ不発」として一般化することは不適切であり、**「終端ラッチ機構と目標進入閾値の不整合によるスタック」** として明確に区別して記録する。

### 4.2 TC 03（PickCubeFar, Seed 3204: 1,200 steps タイムアウト）の分析
- モジュール介入は Base のみ（1,200 steps）。局所パッチの問題ではなく、Base 自体の把持接近角度がキューブの特定初期姿勢と干渉し、把持判定を満たせないままステップ上限に達した。基盤身体能力の物理限界を反映している。

## 5. 命題検証への位置付け（現時点での客観的到達度）

1. **H4（実解放）**:
   - Temporary MLP を参照しない 39,817 bytes の CART 群のみで独立別プロセス実行し、複数課題で動作することを確認した（モデルファイル依存の切り離しとしての初期的支持）。ただし、プロセス常駐 RAM 削減の実測は含まれない。
2. **H6（合成転移）**:
   - 評価条件の一部（3010, 3013）にルーター学習データとの重複が存在し、また目標位置による成否のばらつき（3010, 3015 は成功、3013 は失敗）が確認されたため、本評価をもって「ゼロショット合成転移が確立された」とすることはできず、**「未決着（新規配置への汎化候補と保留組合せ転移の厳密な分離検証が必要）」** と判定する。
